What a screen reader hears

  1. While sending: “Adding you to the list” (polite live region)
  2. On success: focus moves to the result, “Check your email. We sent a confirmation link.”
  3. On failure: the alert, as role="alert"
L2-097

“We couldn’t add you just now”

Details kept, a reference to quote, and “Try again” once the API is back.

The reference

export function failureReference(correlationId: string | null): string {
  return (correlationId || crypto.randomUUID()).slice(0, 8);
}
  • From the response's X-Correlation-ID, or made up when there is no response
  • 5xx, network failure or more than 15 seconds: the same error state

L2-104.5

HTTP 429 after 10 an hour

The page shows the failure state and never retries by itself.

Two limits

Per IP address

More than 10 sign-ups an hour → 429 with Retry-After

Per email address

More than 3 a day → same answer, no more email that day

Still to mock: a rate-limited message that names the wait (L2-097.5).

Things to remember

  • Role, email, optional business name for caterers, ticked consent. Nothing else.
  • Every problem at once, checked again by the server; failures keep what was typed
  • Always “Check your email”: the page never reveals who is on the list
