Spacing

White space is Sweet Hand's main divider. A 4px scale, tight inside components and generous between them, keeps screens calm enough for the food photos to lead.

Overview

The reference design separates things with space, not lines: a wide gap between the filter column and the photo grid, big rows between caterer cards, and a short gap between a caterer's name and its "cuisine · area" line. The spacing scale encodes that rhythm so every screen in the 436 mocks uses the same handful of distances.

The scale is built on 4px (0.25rem). Token names are multiples of the base: --space-4 is 4 × 4px = 16px. Small steps are dense (2, 4, 8, 12, 16, 20, 24px) for component internals; large steps jump (32, 40, 48, 64, 80, 96, 128px) for layout. All values are rem, so spacing grows with the reader's text size.

Spacing tokens are fixed; what changes with the viewport is the layout tier built on them (--layout-gutter, --layout-margin, --layout-section-gap), documented on Layout.

Where these came from. The scale is the mocks' draft unchanged. The style harvest found every spacing value in ui.css on the 4px grid except sub-pixel optical nudges inside text (0.1em code padding, the 1px negative margin that tucks a tab's bar under the border) and the 2px --space-0-5 step, which exists for hairline gaps such as star spacing and the switch thumb inset. Off-scale values in individual mocks (9rem, 11rem, 16rem, 22rem) are mock-only positioning of notes and toasts, not product spacing.

Inside versus between

One rule decides almost every gap: space inside a group is smaller than the space between groups. A caterer's name sits 4px above its meta line, the photo sits 20px above the name, and the next card starts 48–64px away. The eye groups by proximity, so no border or card is needed.

Control heights

Three heights for everything you can press or type into, so a button, an input and a select line up in one row. Medium (44px) is the default because it already meets the phone touch target (L2-065.1). Small (36px) is a desktop density, from 48rem only: below 48rem (XS and SM) every compact control grows to 44px through one rule at the end of components.css, so phones never get a target under 44 × 44px.

Usage

  • Use the tokens. Every margin, padding and gap is a --space-* token. If a design needs 14px, it needs 12 or 16.
  • Use gap, not margins, inside components. .stack (16px), .stack--sm (8px), .stack--lg (32px) and .cluster (12px) set rhythm without margin collapse surprises.
  • Separate with space before lines. Reach for a bigger gap first; add a hairline divider only where space alone is ambiguous (dish rows, table rows, list rows).
  • Grow between, not inside. On larger screens the layout gaps grow (gutters, margins, section gaps); component padding stays the same.
  • Keep controls on the height scale. Do not stretch a button with padding; choose sm, md or lg.
  • Respect safe areas. Fixed bars add env(safe-area-inset-bottom) to their bottom padding (sticky enquiry bar, reply box, sticky form actions).

Accessibility

  • Touch targets (2.5.8, L2-065.1). On XS and SM every interactive control is at least 44 × 44px with at least 8px (--space-2) between neighbouring targets. Medium controls meet this by height; compact controls (.btn--sm, .chip, .menu__item, .input--sm, .choice, .toast__action, breadcrumb links, close and remove buttons) grow to 44px below 48rem and only take their 36px or 24px size from 48rem, where WCAG 2.5.8 (24px) applies.
  • Spacing survives text resizing. Because every value is rem, a reader who sets 20px text gets proportionally larger gaps and taller controls, and nothing overlaps.
  • Text spacing (1.4.12). No component uses fixed heights for text, only min-height, so overriding line, word and letter spacing never clips content.
  • Focus has room. The focus ring sits 3px outside the element; gaps of at least --space-2 between controls keep neighbouring rings from overlapping.
