Responsive

Most people find a caterer on a phone. Every screen is designed at 360px first and then given room, columns and side panels as the viewport grows, without ever scrolling sideways down to 320px.

Overview

Base styles are the phone layout. Breakpoints only add: a second and third column, a filter bar, then a filter column; a side panel on the caterer page; the inbox list beside its thread. Nothing is designed at desktop width and squeezed down.

  • 360px is the design width. Every mock is drawn there first. 320px must still work: no horizontal scrolling, no clipped text, nothing overlapping (L2-064.2, L2-019.4).
  • Breakpoints are in rem and use min-width, so they follow the person's text size. "Hide below" rules use the breakpoint minus 0.01rem.
  • Tokens change, components follow. --layout-columns, --layout-gutter, --layout-margin, --layout-topbar-height and the display type sizes change at 48rem and 62rem in tokens.css; components read them instead of writing their own queries where they can (see Layout for the values).

When a component has two genuinely different forms (a filter bar and a filter column, a sticky bar and a side panel), render both and show one with these classes, rather than rearranging one element with many queries. Both forms must hold the same content and the same accessible names.

Touch, pointer and the device

  • Targets. Below 48rem every target is at least 44 × 44px with 8px between neighbours (L2-065.1). The default control is already 44px; see target sizes.
  • No hover dependency. Anything revealed on hover is also revealed on focus, and on touch screens (@media (hover: none)) it is simply visible, as with table row actions. Tooltips repeat information that is also available by tap (L2-065.3).
  • (pointer: coarse) is not used to grow targets. They are already large enough; growing them per device makes layouts shift unpredictably.
  • Safe areas. Pages set viewport-fit=cover. Fixed and sticky bottom elements add env(safe-area-inset-bottom) to their padding: the sticky enquiry bar, dialog panels, sheet footers, the phone reply box, sticky form actions, toasts and the footer. The site header, sheet headers and the photo viewer bar add env(safe-area-inset-top).
  • Dynamic viewport height. Full-height layouts use 100dvh (page shell, auth layout, full-screen enquiry dialog, dialog max height) so mobile browser chrome never hides the submit button.
  • On-screen keyboard. The focused field must stay visible above the keyboard (L2-026.4); the phone reply box stays pinned above it (L2-036.3). Fields use input types that bring up the right keyboard: type="email", type="tel", inputmode="numeric" for guests, autocapitalize="characters" for postal codes, type="date" (L2-065.2).
  • Rotation. Turning the device keeps typed input and the scroll position (L2-064.3). No layout locks orientation.
  • Swipe is never the only way. The gallery carousel can also be stepped with buttons and opened in the viewer, which has Previous and Next.

Usage

  • Write the phone layout as the base rule, then add @media (min-width: 36rem | 48rem | 62rem | 75rem). Use max-width only for "hide below" rules, as 47.99rem and so on.
  • Prefer intrinsic layouts (flex-wrap, minmax(0, 1fr), min(100%, …)) to a new breakpoint.
  • Never add a breakpoint value outside the scale. If a component breaks between two breakpoints, fix the component.
  • Long names wrap: caterer names clamp to two lines on cards with the full name in the link; buttons may use .btn--wrap. Never truncate an error message or a price.
  • Keep DOM order equal to visual order at every size. Don't reorder with order or grid placement in a way that changes reading order.
  • Spacing never scales with viewport width; the token changes at a breakpoint.

Accessibility

  • Reflow (1.4.10). Content reflows at 320px CSS width, which is also what 400% zoom on a 1280px window produces. Only data tables scroll sideways, inside their wrapper.
  • Resize text (1.4.4). Because breakpoints are in rem, doubling the text size moves layouts to their narrower form instead of overflowing. At 200% zoom on a 1280px window nothing is lost (L2-069.3).
  • Orientation (1.3.4). Both orientations work everywhere.
  • Focus not obscured (2.4.11). The sticky enquiry bar and reply box reserve space with bottom padding (.has-sticky-cta) so focused content is never hidden behind them.
  • Same content, same names. The phone and desktop forms of a component (Filters sheet and filter column; sticky bar and side panel) expose the same options with the same accessible names.

Tokens

Responsive behaviour has no tokens of its own. The breakpoint, column, gutter, margin, container, sidebar, panel, dialog and sheet width tokens (--layout-*) are documented on Layout; the target sizes on Accessibility; the display type sizes that grow at 62rem on Typography.
