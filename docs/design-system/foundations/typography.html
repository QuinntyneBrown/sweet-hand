Typography

One geometric sans, nine sizes, four weights. Text is short and confident: bold names, quiet supporting lines, and the food photos doing the rest.

Overview

The reference design sets a bold geometric grotesque wordmark over a quiet text-only nav, a vertical filter list at 18px and short captions under round photos. The system keeps exactly that: large, tight, bold headings; a 16px body with generous line height; and a muted 14px line for the supporting detail ("Jamaican · Pickering").

Type has three tiers, like colour. Primitives (--font-family-*, --font-size-*, --font-weight-*, --line-height-*, --letter-spacing-*) are building blocks. Roles (--text-*) combine them into a font shorthand, and components use roles: font: var(--text-label). A component may adjust one primitive on top of a role (for example a button label is --text-label at --font-size-md), but never invents a size.

All sizes are in rem, so they follow the reader's browser text size. Only the two largest steps change with the viewport.

Figtree is first in the stack: an open, friendly geometric sans close to the reference's type, with tabular figures and a full Latin set for names like Jean-Robert, Ollivierre and Paramaribo. The fallbacks are chosen to keep the same proportions when Figtree is not loaded (the mocks open from disk without web fonts): Instrument Sans, Avenir Next / Avenir on Apple systems, Segoe UI Variable Display and Segoe UI on Windows, then system-ui, Roboto, Helvetica Neue and Arial.

The licensed web font is still an open decision (mocks README, question 11). When it lands, load it with font-display: swap and keep the fallback list so text never waits for a download.

The mono stack is only for inline code and code blocks. No product screen in the mocks uses it: certificate numbers (FH-2024-118734) and report numbers (R-2047) stay in Figtree.

Responsive display sizes

Phones cannot fit a 64px caterer name, and laptops make a 36px page title look timid. So the two display steps are redefined in tokens.css at the LG breakpoint (62rem, 992px), and every role built on them follows automatically. Nothing else in the scale moves.

Line height and letter spacing

Line height is unitless so it scales with the size. Tight for the big bold roles (they rarely wrap past two lines), snug for small headings and card titles, normal (1.5) for everything you read, and relaxed (1.65) for long-form pages. Letter spacing is tightened on bold headings and the wordmark, and widened only for short uppercase overlines.

Where these came from. Fifteen roles come straight from the mocks' draft and are used in ui.css (most often --text-body-sm and --text-label, 44 uses each). --text-prose is new: the About, Privacy and Terms mocks set long text in .prose, which reads --text-body-lg at line height 1.5, which is cramped for paragraphs of policy; the role adds the relaxed 1.65 line height the draft defined but never used.

Measure and wrapping

Paragraphs stop at --layout-measure (62ch, about 10–12 words per line). Every <p> has it by default in components.css, and .measure applies it to anything else; reviews, enquiry messages and the policy pages all rely on it. The token itself lives on Layout.

  • Headings use text-wrap: balance so a two-line title splits evenly instead of leaving one word behind.
  • Paragraphs use text-wrap: pretty to avoid a single short last line.
  • Names and user text (caterer names, messages, reviews) use overflow-wrap: anywhere so a long unbroken string cannot push the page sideways at 320px.
  • Caterer names on cards clamp to two lines; the full name is on the caterer page.
  • Truncation with an ellipsis is only for one-line UI (the sticky enquiry bar's caterer name, inbox previews), never for content someone needs to read in full.

Numbers, money and dates

Figures that line up in a column or change in place use tabular numbers (font-variant-numeric: tabular-nums): prices on the menu, filter counts, stats, the rating summary, queue wait times, table number columns and the unread badge. Running text keeps proportional figures.

4.7 · 23 reviews

Filter counts and the rating summary use tabular figures.
  • Money is CAD with a dollar sign and no currency code in the product: "From $18 per person", "$14 per litre", "about $2,600 before tax".
  • Dates in lists: "Sat 21 Nov" (add the year when it isn't 2026); on detail screens: "Saturday 21 November 2026".
  • Times: "9:42 a.m.", "6 p.m.", in America/Toronto.
  • Ranges use an en dash without spaces: "20–300 guests", "1:00–3:00 a.m.".

The full number and date rules are on Content.

Usage

  • Use roles. font: var(--text-body-sm), not a size, weight and line height set separately. Add a primitive only to adjust one property of a role.
  • One h1 per page, then h2 for sections and h3 inside them. Pick the heading level by structure and the role by appearance; they usually match.
  • Few sizes per screen. A caterer card is two sizes (card title and body-sm). A screen with more than four sizes is usually missing hierarchy elsewhere.
  • Muted, not smaller. To push a line back, use --color-fg-muted before dropping a size.
  • Sentence case everywhere, including buttons and headings. Uppercase only for overlines, which stay under four words.
  • No italics for emphasis in UI. Use weight. Italics are for quoted titles in reviews only.
  • Keep the wordmark role for the wordmark. It has line height 1 and would clip descenders in running text.

Accessibility

  • 12px minimum. Nothing is set smaller than --font-size-xs, and xs is only for short captions, counts and tags, never for sentences a person must read to act.
  • Resizable text (1.4.4) and reflow (1.4.10). Every size is in rem, so browser text settings apply; at 200% zoom in a 1280px window (640 CSS px, the SM class) every page reflows to one column with no horizontal scrolling (L2-069.3).
  • Text spacing (1.4.12). No text container has a fixed height; content survives line height 1.5×, paragraph spacing 2×, letter spacing 0.12em and word spacing 0.16em.
  • Line height. Body text is 1.5 and prose 1.65; tight line heights are limited to large bold headings.
  • Large text. Text at 24px or larger, or 18.66px bold, counts as large (L2-069.1). The system does not rely on that exception: muted and subtle text pass 4.5:1 at every size.
  • Headings are real headings. Visual roles never replace <h1>–<h4>; a card title inside a listing is an <h3> or a link, not a styled <div>.
  • Language. Pages declare lang="en-CA"; caterer-written text in Haitian Creole or French can be marked with its own lang so screen readers pronounce it.
