Foundation

Iconography

Icons are small, plain outlines that support a word and rarely replace one. They are drawn on a 24-unit grid with a 2-unit round stroke in the colour of the text beside them.

Overview

Sweet Hand shows food, not pictograms. Icons appear where they speed up recognition of a familiar action (close, search, back, edit), mark status alongside text (success, warning, error), or stand in for a photo that has not loaded. Every icon in the product is an inline <svg class="icon"> copied from the icon sheet; there is no icon font and no sprite to load.

  • Outline only. One style for every icon: open shapes, no fills. The single exception is the rating star, which fills inside .stars so a rating reads at a glance.
  • Text first. Most icons sit beside a visible label ("Add photos", "Download my data"). Icon-only controls are limited to universal actions in tight spaces: close, menu, search, previous and next, and row actions such as move, edit and remove.
  • Inherit colour. Icons draw with currentColor, so they are ink in ink text, pepper in a selected filter and muted grey in a muted label, in both themes, with no extra tokens.

Grid and stroke

  1. 24-unit canvasviewBox="0 0 24 24", with about 2 units of padding so strokes never touch the edge. Shapes sit on whole or half units.
  2. 2-unit strokestroke-width: var(--icon-stroke) (2), round caps and joins, fill: none. The stroke scales with the icon: 2px at 24px, 1.67px at the default 20px.
  3. Colour from textstroke: currentColor. Set color on the parent, never a stroke colour on the icon.

All of this comes from one rule in components.css, so an icon's markup is only its paths:

.icon { width: var(--icon-size-md); height: var(--icon-size-md); fill: none;
  stroke: currentColor; stroke-width: var(--icon-stroke);
  stroke-linecap: round; stroke-linejoin: round; flex: none; }

Drawing a new icon

  • Start from a 24 × 24 artboard with a 2-unit keyline; use 2-unit strokes, round caps and joins, and no fills.
  • Match the visual weight of the sheet: simple geometric shapes, at most three or four strokes, corners rounded by the stroke rather than drawn.
  • Export paths only: no style, fill, stroke or class attributes inside the SVG, no width/height, no <title>.
  • Add it to this sheet with its name and use before anyone ships it. One glyph means one thing everywhere (WCAG 3.2.4).

Sizes

Twenty pixels is the default: it sits on the cap height of 16px body text and fills a 44px button comfortably. The other sizes belong to specific places; pick by context, not by taste.

Colour

Icons take the colour of their context. The few places that colour an icon on purpose do it through the parent's color, using status or star tokens, and always next to text that says the same thing.

Labelling

An icon is either decoration beside words, or the only visible label of a control. The markup differs.

The camera is decorative; the four icon buttons are named by aria-label, each naming its object.
HTML
<button class="btn" type="button">
  <svg class="icon" aria-hidden="true" viewBox="0 0 24 24">…</svg>Add photos
</button>
<button class="icon-btn" type="button" aria-label="Edit Curry goat">
  <svg class="icon" aria-hidden="true" viewBox="0 0 24 24">…</svg>
</button>
  • Every SVG icon carries aria-hidden="true", including the one inside an icon-only button. The name belongs to the control, not the drawing, and no <title> goes inside the SVG.
  • Icon-only controls carry aria-label with a verb and, in a list, the object: "Edit Curry goat", "Move photo 2 down", "Remove Sorrel", "Close filters", "Next photo" (L2-068.4). Repeated rows must not all be called "Edit".
  • A count badge on an icon button joins the name: the inbox link reads "Inbox, 1 unread enquiry", using the badge's own aria-label.
  • Status icons never stand alone. The alert title, "Saved" or the status label says the same thing in words (WCAG 1.4.1, L2-069.5).
  • Stars are hidden; the number is read. .stars is aria-hidden="true" and the visible "4.7 · 23 reviews" is the text alternative.
  • Icon-only buttons on desktop may add a tooltip repeating the label; on touch the label must already be clear, because there is no hover (L2-065.3).

Usage

  • Use the icon from this sheet whose name matches the action. If none matches, write the label without an icon rather than borrowing a near miss.
  • One icon per button, leading the label. Chevrons trail, because they point where the control goes.
  • No icons in headings, in body copy or as bullets. Food photos and short headings carry the page.
  • Never use an icon as the only marker of a dietary need or allergen: tags are words ("Contains nuts", "Halal").
  • Keep icons the colour of their text. Don't place an icon in a coloured circle unless it is an empty state, a dialog's status icon, or the avatar placeholder.

Accessibility

  • Non-text contrast (1.4.11). Icons that carry meaning keep 3:1 against their background in both themes. Decorative icons beside text inherit the text colour, which already passes 4.5:1.
  • Images of text (1.1.1). Decorative icons are aria-hidden="true"; icon-only controls have aria-label.
  • Forced colours. Because icons draw with currentColor, Windows High Contrast recolours them with the surrounding text automatically.
  • Consistent identification (3.2.4). One glyph, one meaning: the flag only ever means "report", the shield only "security or audited access".
