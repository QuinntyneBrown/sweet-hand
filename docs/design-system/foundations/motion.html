Foundation

Motion

Motion in Sweet Hand is quiet and quick: things fade and settle, overlays rise into place, photos lean in a little when you point at them. It explains where something came from and never makes anyone wait.

Overview

Every transition and animation in components.css reads a --duration-* and an --ease-* token. Nothing hard-codes a time. That one rule gives the product a consistent rhythm, and it makes reduced motion a token change: prefers-reduced-motion: reduce zeroes the transition durations in tokens.css, so components need no media queries of their own.

  • Short. Hover and press colour changes take 120ms; menus and toasts 200ms; dialogs, sheets and the photo zoom 320ms. Nothing that blocks input runs longer than 320ms.
  • Purposeful. Motion shows where something came from: a phone sheet rises from the bottom edge, a side sheet slides in from the right, a dialog scales up from the centre. There is no decorative motion.
  • Calm. No bounce, no parallax, no auto-advancing carousel. The gallery moves only when someone swipes it.

Each button below replays a demo. With reduced motion turned on in your operating system, the dots jump straight to the end, which is exactly what the product does.

Durations

Five transition durations cover every state change. Pick by distance and size: small, local changes are fast; big surfaces that enter the screen are slow.

All five use --ease-standard. Each demo sets --demo-duration to the token it names.

Easing

Things that arrive decelerate into place (--ease-enter); things that leave accelerate away (--ease-exit); things that change in place use --ease-standard. The demos run at 500ms so the curves are easy to see; in the product each easing pairs with the duration in the table above.

Loops and delays

Three tokens are not transitions. Two time repeating animations; one is a wait before a tooltip appears.

Processing Report
Spinner: one turn per --duration-loop-fast. Skeleton shimmer, indeterminate bar and pulse: --duration-loop. Point at or focus the flag: the tooltip waits --duration-hover-delay.

--duration-loop-fastOne spinner revolution, linearInside busy buttons (aria-busy="true") and the photo viewer while a photo loads.

Usage

  • Always write transition: <property> var(--duration-*) var(--ease-*). Never a literal time, never all: list the properties that change.
  • Animate opacity, translate, scale and colours. Never animate width, height, top or margin on large elements; the only exceptions are the progress bar width and the small gallery dot.
  • Use a CSS animation for entrances (it plays when the element appears) and a transition for state changes (it follows the state both ways).
  • New loops need a reason a person cares about ("still loading", "still processing") and must stop under reduced motion unless they report status.
  • Nothing moves on its own: no auto-advancing gallery, no ticker, no attention-seeking wiggle on the enquiry button.
  • Never delay content to show an animation. Pages render straight away; skeletons replace content only while it is genuinely loading.

Accessibility: reduced motion

L2-069.4 asks that with prefers-reduced-motion: reduce, "animations are turned off or limited to an opacity fade of 200ms or less" (WCAG 2.3.3). The system meets it in two layers.

  1. Tokens. tokens.css sets --duration-fast, --duration-base, --duration-slow and --duration-deliberate to 0.01ms. Every transition and every entrance animation that reads them becomes instant. (0.01ms rather than 0, so animationend and transitionend still fire for scripts that wait for them.)
  2. Components. The motion block in components.css stops what the tokens cannot reach because loops keep their own durations.

Test it: in Chrome DevTools open Rendering and set "Emulate CSS media feature prefers-reduced-motion" to reduce, then open a dialog, the Filters sheet and a toast, and hover a caterer card. Nothing should slide, scale or shimmer, and the busy button spinner should still turn.

Other motion rules: nothing flashes more than three times a second (2.3.1); nothing moves for more than five seconds on its own except loading indicators, which end when loading ends (2.2.2); motion never carries meaning alone, so a toast is also announced by its live region and a loading region carries aria-busy="true".
