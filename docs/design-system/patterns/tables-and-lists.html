Pattern

Data tables and lists

Sweet Hand shows collections as rows, not grids of cells: a photo or initials, a name, one quiet line, a status word. Real tables are kept for records people compare across columns, like the audit log and metrics.

Overview

The brand is minimal text and round photos, so collections are lists of rows separated by hairlines, with no card borders, no zebra stripes and no column headers unless the data truly needs them. Each row type is a component: inbox row, queue item, list rows (.list__item, .admin-row, .edit-row), review, dish and the description list. The table exists for the two places where people scan down a column and compare: the audit log and the metrics figures.

  • A row is one thing: one enquiry, one caterer waiting for review, one cuisine. Its name comes first and is the link.
  • Rows read on a phone without change. A table needs sideways scrolling at 360px; a row does not.
  • Status is a word plus a shape (status label), never colour alone.
  • Order is stated, not chosen. Lists have one sensible order and say so: "newest first", "oldest first", "A to Z".

Density

  • One density for rows: 16px vertical padding (20px for queue items, 24px for reviews) and at least a 44px target, because most people use a phone.
  • Tables have default (16px cells) and .table--dense (8px) for operator figures on large screens; dense tables keep 44px tall controls inside.

Filtering

  • Status segments (.segmented) filter one list by a single attribute; each is a link with a count, the current one in pepper; the choice lives in the URL so Back restores it.
  • Toolbar (.toolbar) holds several operator filters (operator, action, target, dates) applied together with Apply. Changing a field does nothing until Apply, so a half-set range never loads.
  • Search field narrows by name ("Business or owner name"); combined with a segment, the empty state names both: "No suspended caterers match “Pelau”".
  • The public listing uses the filter list with instant results instead (see Navigation).

Sorting

No mock lets people re-sort. Every list has one fixed order, stated in its accessible name or subtitle: inbox and enquiries by latest activity, newest first; the queue oldest first; cuisines A to Z; the audit log newest first. If a table ever needs sorting, the header cell gets aria-sort and a button (.table th[aria-sort] button), and only one column sorts at a time.

Pagination or show more

  • Numbered pages for long, open-ended lists (24 caterers or 20 enquiries per page): "Showing 1–24 of 60" above the page links; the page number is in the URL; an impossible page number shows page 1.
  • Show all in place for short, bounded lists on one record: "Show all 18 dishes" expands without a reload, keeps focus on the toggle and announces "18 dishes shown".
  • No infinite scroll: the footer must stay reachable, Back must return to the same place, and screen-reader users need a count.

Responsive behaviour

  • Rows keep their layout at every width: long names truncate, meta wraps. .queue-item--stack moves the wait time under the title below 36rem; .edit-row moves its actions under the dish below 36rem; .admin-row wraps its actions to a new line.
  • Inbox: below 62rem only the list shows and a row opens the thread full width; from 62rem the list sits beside the thread.
  • Tables scroll sideways inside .table-wrap (a focusable region), never the page; the first column carries the most important value (When). Metrics show charts and offer "Show as a table" per chart.
  • Toolbars wrap; each field keeps a 10rem minimum; Apply stays last.
  • Pagination keeps Previous, the current page, neighbours and Next at 320px.

Accessibility

Role and pattern

Row lists are <ul> with an aria-label that includes the order ("Dishes, in the order they appear on your page"). A whole-row link puts the name first so the link's name starts with it; decorative photos have alt="". Tables use <caption>, <th scope="col">, and sit in role="region" tabindex="0" labelled by the caption so keyboard users can scroll them (APG Table). Pagination is a <nav aria-label="Pagination"> with aria-current="page".

Keyboard

KeyAction
TabOne stop per row link; then each row action in order (Move up, Move down, Edit, Remove).
← → in a focused table regionScrolls the table sideways.
Enter on Move up / Move downMoves the row; focus stays on the same button of the moved row and the new position is announced.

Focus

Row links draw the focus ring around the whole row. After Remove is confirmed, focus moves to the next row (or the previous one at the end). After Apply, focus moves to the result count.

Labelling

Row actions name their object ("Remove Chicken pelau", "Retire Bahamian"). Unread rows start with a visually hidden "Unread.". Counts in segments are read as part of the link ("Open 1").

Motion

Only background colour changes on hover (120 ms). Reordered rows move without animation under reduced motion.

Touch

Rows are at least 72px tall on phones; icon actions are 44px and never closer than 8px; row actions are always visible on touch screens (@media (hover: none)).

Content

  • Row meta joins facts with a middle dot: "Sat 21 Nov · 120 guests", "Jamaican · Oshawa", "Admin · Authenticator app · Active now".
  • Row times are relative and short: "9:42 a.m." today, "Yesterday", "Thu" this week, "5 Sep" earlier, "Sat 12 Jun 2027" in another year. Tables write the full Toronto time: "Fri 9 Oct, 4:30 p.m.".
  • Waits count days: "Waiting 2 days". Counts read as phrases: "2 published caterers", "No published caterers", "23 reviews · 1 without a response".
  • Column headers are one or two words in sentence case: "When", "Operator", "Before → after".
  • Missing values in tables show an em dash (—), with .na styling, never "N/A" or blank.
