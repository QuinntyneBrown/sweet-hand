Pattern

Navigation and page structure

A bold wordmark, a quiet text nav and one clear heading per page. Each role gets the same header with its own links; work areas add a side list of sections that becomes a stacked list on phones, and every deeper screen has one way back.

Overview

Sweet Hand has three audiences in one product: customers browsing and enquiring, caterers running their profile, and operators reviewing and moderating. They share one site header and one set of page layouts (container and grid), and differ only in their links, the tag beside the wordmark, and whether a work area has a side navigation.

  • Header: wordmark left, a few text links right, then icon buttons (search, menu) and the avatar. The current link is semibold ink; nothing in the header is pepper.
  • Phones: links that do not fit move into the site menu sheet; the header keeps the wordmark, search and the menu button (with the unread count on it).
  • Work areas (caterer dashboard, operator console): a side list of sections from 62rem; below that, the Overview page lists the sections and each section page has an eyebrow back link to Overview.
  • One heading per page in the .page-intro, with an optional status or subtitle line under it. No breadcrumb trails: Sweet Hand is never more than two levels deep.

Accessibility

Role and pattern

Every page has a skip link to #main, a <header>, a <nav aria-label="Primary">, one <main> and one <h1>. Work areas add <nav aria-label="Dashboard">; the preview pane is an <aside> labelled by its heading. The current page uses aria-current="page"; status segments are links (with aria-current) because each is a URL. The avatar is a menu button (APG Menu Button); the menu icon opens a modal sheet (APG Dialog).

Focus

After a client-side navigation focus moves to the new page's <h1>. The sticky header and bottom bars never cover the focused element (scroll-padding-top is the header height; WCAG 2.4.11).

Labelling

Counts are part of the name: "Inbox, 1 unread enquiry" via aria-label on the badge, "Menu, 1 unread enquiry" on the menu button. The avatar says whose account it is: "Account menu for Marcia Thompson". Two navs on a page have different labels.

Motion

The site menu slides up on phones and in from the right on wider screens; reduced motion removes the slide. Page changes have no transition.

Touch

Header links, icon buttons, the avatar and filter-list rows are all 44px tall; section-list rows are 72px.

Content

  • Nav labels are one or two plain nouns: "Caterers", "Occasions", "Inbox", "Dashboard", "My page", "Review queue", "Breach register".
  • Eyebrow links name the place they go: "Caterers", "Overview", "Back to inbox". Use "Back to …" only when the parent's name alone would be unclear.
  • The page heading is the thing itself: "Pelau House", "Business details", "Inbox". Subtitles are one short line: "Your conversations with caterers", "Append-only · newest first · kept for 7 years".
  • Section-list meta says the state in a few words: "6 photos", "23 reviews · 1 without a response", "Replace photos 2 and 5".

Back behaviour

  • Filters, status segments, sort and page number live in the URL (/caterers?cuisine=jamaican&area=scarborough, ?status=open), so the browser's Back restores the previous view and its scroll position.
  • The eyebrow link always goes to the parent, not "history back", so it works from a shared link.
  • Closing a dialog or sheet returns focus to the control that opened it. Whether the phone back gesture should close full-screen overlays (enquiry, filters, site menu) is not shown in the mocks; record it as an open question before implementation.
  • After sign-in, people return to where they were, with an unfinished enquiry restored.
