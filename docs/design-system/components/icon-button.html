Icon button

A 44px round button that holds one outline icon and no visible text: the header search, the phone menu, Close, and the move arrows under each photo.

WCAG 2.2 AAStatus: stableNative <button> or <a>.icon-btn

Overview

Use an icon button where space is tight and the icon is understood without a word: the site header, a dialog's Close, the photo viewer, and the repeated actions on rows and photo tiles. Every icon button still has a name, given by aria-label.

  • Ghost (.icon-btn) has no border and no fill at rest. It is the header search ("Search by area or postal code"), the phone menu, dialog Close, and "Move photo 2 up" on a photo tile.
  • Outline (.icon-btn--outline) adds a hairline ring so the target shows against a large photo. The photo viewer gets it automatically (.viewer .icon-btn) for Previous, Next and Close.
  • With a count puts a .badge--count on the corner: the phone inbox link, "Inbox, 1 unread", or the caterer's "Enquiries, 2 unread".
  • As a link (<a class="icon-btn">) goes somewhere instead of doing something, like the phone inbox link. Link semantics stay.

Don't use an icon button when there is room for a word. The phone browse bar says "Area or postal code" on a ghost button with an icon, because a pin alone is ambiguous. An icon button is never the screen's main action. The thread's Send button is the exception: it is a primary .btn.btn--icon, documented on the button page. When one trigger offers several actions, use a menu.

Anatomy

  1. Container44px circle (--target-comfortable, --radius-full). Transparent at rest; --color-bg-subtle on hover. The outline variant adds a 1px --color-border-default ring.
  2. Icon24-unit outline icon at 20px (--icon-size-md), 2px stroke, currentColor, aria-hidden="true".
  3. Count badge (optional).badge--count pinned top right, at least 20px, sorrel with white figures. It is aria-hidden; the count is in the button's name.

Outline, in the photo viewer

The ring is decorative (the glyph identifies the control); it shows where the 44px target is next to a large round photo.

Row and tile actions

The first photo cannot move up, so that button is disabled rather than hidden and the arrows stay in place. Each name says which photo or dish it acts on.

Sizes

One size: 44 × 44px with a 20px icon, so every icon button meets the phone target (L2-065) without exceptions. Where a desktop row needs a denser square, use .btn.btn--icon.btn--sm from button: 36px from 48rem, growing back to 44px below it (L2-065.1), with the button's border and variants.

.icon-btn · 44px (--target-comfortable) at every width, beside .btn--icon.btn--sm · 36px (--control-height-sm) from 48rem, 44px below.

Both themes

1
1
  • Disabled uses the native attribute at 50% opacity with no hover fill. Use it at the ends of a list ("Move photo 1 up", "Move photo 6 down") and for a dialog's Close while it is busy ("Suspending Pelau House" keeps Close disabled until the server answers).
  • Pressed (aria-pressed="true") and expanded (aria-expanded="true") keep the hover fill while on. This is for toggles and for the trigger of an open menu or popover. No current mock uses an icon toggle, and a background-only pressed state is too faint (see Sources), so a pressed icon button also turns its glyph pepper.
  • Current page: the phone inbox link carries aria-current="page" on the inbox and its threads. It shows the glyph in --color-fg-accent, pepper for "you are here", matching the text link in the wide header.
  • Busy is not an icon-button state. A busy action belongs to a .btn (aria-busy); the thread's Send reply is .btn--primary.btn--icon for that reason.

Responsive behaviour

  • Below 48rem (XS, SM) the header swaps text links for icon buttons. .site-nav__extra links (Caterers, Occasions, Inbox, the avatar) hide; .site-nav__menu icon buttons (inbox link with count, Menu) show. Search shows at every width. At 320px the row is wordmark + 3 × 44px + 2 × 4px gaps, and the "for caterers" tag drops below 22.5rem, so the header never scrolls sideways.
  • From 48rem (MD up) the phone-only icon buttons hide and the text links return. Search stays an icon button: there is no free-text search box in the header (mocks README, open question 8).
  • Photo viewer: Previous and Next flank the photo at every width. From 48rem the gap between control and photo grows from --space-2 to --space-8.
  • Photo tiles (2 / 3 / 4 columns at XS / MD / XL) centre their move arrows under the caption and wrap if a tile is narrower than 92px.
  • An icon button never shrinks with the viewport. If a row cannot fit its icon buttons, the row wraps.

Theming

The icon button has no component tokens: the glyph is currentColor from --color-fg-default, the hover and pressed fill is --color-bg-subtle, active is --color-bg-subtle-hover, and the outline ring is --color-border-default. The count badge brings its own --color-danger-solid and --color-fg-on-danger.

In dark the glyph flips to stone-100 and the fill to stone-800; the badge becomes sorrel-300 with near-black figures. To re-skin one context, set color on the container (the glyph follows) rather than editing .icon-btn:

/* Icon buttons on an inverse surface inherit its text colour */
.ds-example__canvas--inverse .icon-btn { color: var(--color-fg-inverse); }

Accessibility

Role and pattern

Native <button type="button"> (APG Button), or <a href> when it navigates (the inbox link). Toggles add aria-pressed. Triggers add aria-haspopup="dialog" or "menu", and a menu trigger also carries aria-expanded and aria-controls.

Keyboard

KeyAction
Tab / Shift+TabMoves to and from the icon button in DOM order (header: search, inbox, menu).
EnterActivates a button or follows a link.
SpaceActivates a button (not a link).
EscCloses the dialog, sheet or menu the button opened and returns focus to it.

Focus

The shared 2px pepper ring with a 3px offset follows the circle, because .icon-btn keeps --radius-full on focus. When a dialog, sheet or the viewer closes, focus returns to the icon button that opened it ("Escape or Close returns focus to the search icon").

Labelling

aria-label names the action and, in a list, the object: "Move photo 3 up", "Edit Sorrel", "Remove Black cake". Inside a named dialog "Close" is enough; the viewer says "Close photo viewer" because it has no visible title. A count goes in the label ("Inbox, 1 unread") and the badge is aria-hidden. Keep the label when pressed. Don't rely on title; add a tooltip only where sighted pointer users need the word as well.

Contrast

Glyph on canvas

Current-page glyph (pepper)
Count on badge

The outline ring (--color-border-default) is decorative: the glyph alone identifies the control at 3:1 or more. Disabled icon buttons are exempt (WCAG 1.4.11).

Motion

Only the background colour transitions, over --duration-fast (120ms). Reduced motion zeroes it. Nothing moves or scales.

Touch

Every icon button is 44 × 44px, so adjacent targets (the header row, a tile's up and down arrows 4px apart) need no extra spacing under WCAG 2.5.8. Nothing depends on hover: there are no hover-only reveals on rows or tiles.

Content

  • Names are verb phrases in sentence case, Canadian English: "Search by area or postal code", "Close photo viewer", "Previous photo", "Move photo 2 down".
  • Name the object in repeated rows: "Remove Curry channa and aloo", spelled as the caterer spells the dish.
  • Counts read as "Inbox, 1 unread" or "Enquiries, 2 unread": noun, comma, number, state. Over 99 the badge shows "99+"; the name keeps the real number.
  • One icon, one meaning, everywhere: the pin means area, the envelope means inbox or enquiries, the two-line icon means the site menu. Never reuse the search icon for filters.
