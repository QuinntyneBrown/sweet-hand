Review

What a customer said about their event, and the caterer's one public answer. Reviews are ruled rows of plain text: who, when, how many stars, what they wrote. The same row is moderated by operators and answered by caterers.

Overview

A review is written by a customer after their event, once the caterer has replied to their enquiry. It shows on the caterer's page as a row in .review-list: first name and initial, the event month, a star score, the text, and optionally "Response from Pelau House". Four audiences see the same component with different parts switched on:

  • Public (caterer page): head, body, response. No actions.
  • Own review (caterer/own-review): a "Your review" badge, the edit window ("You can edit this review until Tue 20 Oct.") and Edit / Delete.
  • Caterer (dashboard reviews): posted date, "No response yet" when unanswered, and Respond / Edit response, which open dialogs/review-response.
  • Operator (admin reviews): the caterer's photo and name lead, "by Priya R." follows, a moderation status explains why it is held or hidden, and Approve / Keep hidden / Restore / Remove open dialogs/moderate-review.

Use a review only for customer reviews. Enquiry conversations are a message thread; reports about a review are listed as list rows or a table, not as reviews; the average at the top of the section is a rating summary.

Anatomy

  1. Author.review__author: first name and last initial ("Marcia T."), --text-label at --font-size-md. Never a full surname.
  2. Date.review__date: the event month ("Event in August 2026"); caterers also see "Posted Tue 1 Sep". Muted, small.
  3. Stars.stars with role="img" "5 out of 5".
  4. Body.review__body: plain text at the reading measure, wraps anywhere; links and markup show as text.
  5. Response.review__response: indented 16px behind a 2px --color-border-default rule, labelled "Response from Pelau House".
  6. Actions (optional).review__actions: small buttons that name the review they act on.

Sizes

Reviews have one size and one density. Body text is capped at the reading measure (--layout-measure) on every screen.

Responsive behaviour

  • The head is a wrapping row: at 360px "Marcia T. · Event in August 2026" fit on one line and the stars drop to the next; from 36rem everything sits on one line.
  • Body and response wrap anywhere (overflow-wrap: anywhere), so a pasted URL never pushes the page sideways (caterer/edge).
  • Actions wrap onto as many rows as they need. Below 48rem the small buttons grow to 44px (L2-065.1); from 48rem they are 36px with 8px between them.
  • On the caterer page the Reviews section is one column at every width; the dashboard caps it at 48rem.

Theming

No component tokens. Author and body read --color-fg-default, date --color-fg-muted, rules and the response bar --color-border-default. The response is set apart by indentation and its label, not by a tinted box, keeping the page flat. Moderation statuses read the status colours (--color-warning-fg for held, --color-fg-muted for hidden); the flagged-text highlight uses the warning background via .diff-new. Dark swaps every one of these through the semantic layer.

Accessibility

Role and pattern

A plain <ul> of reviews under the section's "Reviews" h2 (on the dashboard a visually hidden "Newest first" h2). No widget pattern applies; the actions are buttons that open dialogs (APG Dialog). "Show more reviews" follows the Disclosure pattern with aria-controls.

Keyboard

KeyAction
TabPublic: reviews are not focusable; Tab reaches "Show more reviews". Elsewhere: each review's actions in order.
Enter, SpaceOpens the dialog for that review; closing returns focus to the same button.

Focus

The shared ring on each action. After "Show more reviews", focus stays on the toggle and the newly shown count is announced; after a review is removed, focus moves to the next review's first action (or the list heading if it was the last).

Labelling

Repeated action words carry a visually hidden object: "Respond to Andre C.", "Edit response to Devon W.", "Approve review by Priya R. of Sugar Dumplin". Stars are a single image: "4 out of 5". The response label is visible text, so the response is never mistaken for the reviewer's words.

Motion

None. Rows appear and disappear without animation; skeletons stop shimmering under reduced motion.

Touch

Actions are 44px tall below 48rem and 36px with 8px gaps from 48rem, clearing WCAG 2.5.8 at every size.

Content

  • Author: first name and last initial, "Marcia T.", "Jean-Robert P.". A deleted customer's reviews are removed and the average recalculated (L2-072.3).
  • Date: the event month, "Event in August 2026" (not the posting date: what matters is when they ate). Caterers add "· Posted Tue 1 Sep".
  • Response label: "Response from Pelau House", always the caterer's business name.
  • Edit window: "You can edit this review until Tue 20 Oct."
  • Moderation reasons name the trigger: "Held · contains a phone number", "Held · contains a link", "Hidden automatically · 3 reports", "Hidden by Tomas Reyes".
  • Reviews are shown exactly as written, in any language; markup and links are plain text.
