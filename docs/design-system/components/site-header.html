Site header

A bold wordmark, a quiet text-only nav and a few icons: the header is the first thing on every page and the least loud. It changes with who is signed in, and on phones its links fold into a site menu.

Overview

The site header holds the wordmark and the primary navigation. It follows the reference design: white canvas, no border, no shadow, the wordmark in bold ink at --text-wordmark, and plain text links in muted ink. It scrolls away with the page; nothing about it is sticky.

  • Use it on every page, including auth, error and system pages, so people can always get back to the listing.
  • It has four variants by audience: visitor (signed out), customer, caterer ("for caterers" tag) and operator ("Operator" tag). The tag tells caterers and operators which side of Sweet Hand they are on.
  • Inside a work area (dashboard, operator console) section navigation lives in the side navigation, not in the header; the header keeps only 2 to 3 top-level destinations.
  • Page-level tasks never go in the header. "Send an enquiry" is on the caterer page and its sticky bar; filters are on the listing.

The header uses no pepper red, except on a current icon shortcut (the inbox envelope on the inbox page), which is pepper like every current icon button; it keeps its ink on hover otherwise. The current text link is marked by ink and weight only; pepper is kept for selections in the content below (filters, the side nav, tabs).

Anatomy

  1. Wordmark.wordmark: "Sweet Hand" in --text-wordmark, a link to the audience's home (listing, dashboard or queue). 44px tall.
  2. Area tag (optional).wordmark__tag: "for caterers" or "Operator", a hairline pill in label type. Part of the link's name. Hidden below 24rem.
  3. Nav link.site-nav__link: muted text, 44px tall; current page in ink, semibold, aria-current="page".
  4. Unread badge.badge--count with an aria-label that says what is counted ("2 unread enquiries").
  5. Account triggerbutton.avatar, 44px, initials, opens the account menu. Search and Menu are icon buttons in the same slot.

Legacy .topbar

The base kit also ships .topbar (__brand, __nav, __spacer, __menu): a sticky bar with a surface background and a bottom border, made for a generic app shell. No Sweet Hand mock uses it, and its border and sticky behaviour contradict the flat reference design. It stays in components.css for parity only. Don't use it; use .site-header.

Sizes

The header has one size, which grows with the viewport through --layout-topbar-height: 64px on phones, 80px from 48rem, 96px from 62rem. Its items stay 44px tall at every width.

States

Hover and focus are forced with data-state; the current page uses aria-current="page"; an open menu uses aria-expanded="true".

Responsive behaviour

  • Below 48rem every .site-nav__extra item is hidden and every .site-nav__menu item appears: a Menu icon button that opens the full-screen site menu sheet (dialogs/site-menu), plus an envelope icon with the unread count for customers and caterers, so the inbox stays one tap away. Search stays visible for visitors and customers. At most three icons sit beside the wordmark.
  • Below 24rem (phones narrower than 384px) the area tag ("for caterers", "Operator") hides so the header never scrolls sideways; the wordmark alone still links home.
  • From 48rem the text links show and the phone-only items hide. Height grows to 80px.
  • From 62rem height is 96px; inside work areas the side navigation appears below the header.
  • The header spans the container (--layout-container-max, 90rem) with --layout-margin side padding and respects the top safe area (env(safe-area-inset-top)).

Theming

The header reads --color-bg-canvas (it is the page, not a bar), --color-fg-default for the wordmark and current link, --color-fg-muted for other links and the tag, --color-border-default for the tag's hairline, and the avatar's --color-bg-subtle. In dark the canvas goes near-black and the wordmark near-white; nothing else changes. Don't give the header its own background or a bottom border to "separate" it: the reference design relies on space.

Accessibility

Role and pattern

<header> (banner landmark) containing <nav aria-label="Primary">. The Menu and account buttons follow the APG disclosure idea: aria-haspopup naming what opens ("dialog" for the site menu sheet and the account popover) and aria-expanded while it is open. Opening moves focus into the popup; closing returns it to the trigger.

Keyboard

KeyAction
TabAfter the skip link: wordmark, each nav link, search, inbox icon, Menu, avatar, in that order.
EnterFollows a link; opens search, the menu sheet or the account menu.
SpaceOpens the menu sheet or account menu (buttons only).
EscCloses an open menu and returns focus to its trigger.

Focus

The shared ring wraps each 44px item; nav links have a pill radius, so the ring follows the pill. The header is never sticky, so it can never cover a focused element (WCAG 2.4.11).

Labelling

  • The nav is "Primary"; work areas label their side nav ("Dashboard", "Operator").
  • Icon items name the destination and the count: "Inbox, 1 unread", "Enquiries, 2 unread". The visible badge inside is aria-hidden; on text links the badge itself carries aria-label="1 unread enquiry".
  • The avatar names the person: "Account menu for Marcia Thompson".
  • The wordmark's name includes the tag ("Sweet Hand for caterers"), which tells screen-reader users which area they are in.

Current page is not shown by colour alone: it changes weight (semibold) and is announced by aria-current.

Motion

Link colour changes over --duration-fast; the menu sheet slides in over --duration-slow. Reduced motion removes both.

Touch

Every item is 44 × 44px or larger (--target-comfortable) with at least --space-2 (8px) between items below 48rem and --space-1 from 48rem; icon buttons are circles of 44px, so their visual gaps exceed 8px.

Content

  • One-word destinations, sentence case: "Caterers", "Occasions", "Inbox", "Dashboard", "Enquiries", "My page", "Queue", "Metrics", "Sign in".
  • The product noun is "caterer": "Caterers", never "Cooks" or "Vendors".
  • Tags: "for caterers" (lower case, reads on from the wordmark), "Operator" (a role, capitalised).
  • Counts are numbers only in the badge ("2"); the meaning lives in the accessible name. Above 99 show "99+".
  • No marketing copy, no "Sign up free" button in the header.
