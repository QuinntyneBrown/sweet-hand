Badge

Badges are small pills that add one short fact to something else: how many enquiries are unread, which row is you, which cuisine was just added. They are rare on Sweet Hand; a record's state is a status label, not a badge.

Overview

Sweet Hand uses badges in exactly three ways, and you should need a good reason to add a fourth:

  • Count (.badge--count): unread or waiting items on a navigation link — "Inbox 1" for Marcia, "Enquiries 2" for Kendra, "Queue 7" for operators — and on the phone header's inbox icon.
  • Neutral (.badge): a marker beside a name: "You" in the operator list, "Your review" on the caterer page.
  • Info (.badge--info): "New" beside a cuisine an operator added today.

Prefer a status label for the state of a record (Open, Replied, Published, Suspended…): it is a word plus a shape with no fill, which keeps busy lists calm. Use a tag for dietary and allergen facts about a dish, and a chip for anything you can press or remove. Success, warning, danger and solid badges exist in the kit but no screen uses them today.

Anatomy

  1. Dot6px circle in the text colour (::before); hidden on count and solid badges.
  2. LabelOne or two words, --text-label at --font-size-xs, never wraps.
  3. CountTabular numerals centred in a pill at least 1.375rem wide on --color-danger-solid.

Count on a link and on an icon button

On a text link the badge follows the label. On the phone header the inbox is an icon button and the badge sits on its top-right corner (.icon-btn .badge--count). Both hide the number from assistive technology and say the full meaning once.

Sizes

Badges have one size: 12px label in a pill at least 24px tall (--target-min). Inside an icon button the count shrinks its minimum to 20px (--icon-size-md) so it fits on the corner.

States

Badges are not interactive, so they have no hover, focus or disabled state; the link or row they belong to does. What changes is the value.

Both themes

YouNewSuccessWarningDangerCover2
YouNewSuccessWarningDangerCover2
  • Zero: remove the count badge; never show "0". The link still says "Inbox".
  • Large: show the number up to 99, then "99+"; the hidden text keeps the exact count ("134 items waiting").
  • Updating: when the count changes while the page is open, the badge just changes. Don't announce it; the inbox or queue page has its own live region.
  • "New" lasts for the day the item was added, then disappears.

Responsive behaviour

  • Badges never wrap (white-space: nowrap) and never change size.
  • Below md (48rem) header links with counts move into the site menu or become icon buttons; the count moves with them onto the icon's corner, so it is visible at every width.
  • In wrapping titles (.admin-row__title is a flex row that wraps) the badge drops to the next line as a unit rather than splitting from its pill.

Theming

Tones map to status token families: neutral reads --color-bg-subtle / --color-fg-muted; info, success, warning and danger read their -bg and -fg pairs; solid reads --color-info-solid with --color-bg-surface text; count reads --color-danger-solid with --color-fg-on-danger. No component tokens.

The count is sorrel red, not pepper. Pepper means "selected / you are here"; an unread count is something different, and in dark the two must stay apart (sorrel-600 against pepper-300). In dark every tinted badge flips to a deep background with a light label from the same family.

Accessibility

Role and pattern

A badge is text in a <span>; it has no role. A count whose number alone would be meaningless ("7") is aria-hidden="true", and the meaning is given once: visually hidden text inside the link (", 7 items waiting") or the icon button's aria-label ("Enquiries, 2 unread"). Don't put aria-label on the badge <span>: a generic element can't be named, and support is patchy. See WCAG 1.3.1.

Keyboard

KeyAction
TabNever stops on a badge; it stops on the link or button that contains it.

Focus

No focus of its own. On an icon button the badge sits inside the button's bounds, so the button's focus ring encloses it.

Labelling

Spoken meaning: "Inbox, 1 unread enquiry", "Queue, 7 items waiting", "Enquiries, 2 unread". Neutral and info badges are read as part of the name they follow ("Leah Mohammed You"); keep them to one word so that still makes sense.

Motion

None. Counts change without animation; nothing pulses or bounces for attention.

Touch

Not a target. The count overlaps the corner of a 44px icon button but stays inside it, so it never enlarges or shifts the target.

Content

  • Counts are numerals: "2", "34", "99+". The hidden text uses the noun the page uses: "unread enquiry / enquiries", "item / items waiting".
  • Markers are one word, sentence case: "You", "New". "Your review" is the longest label in use.
  • Never use a badge for a record state ("Published", "Suspended"): that is a status label. Never use one for "Halal" or "Contains nuts": that is a tag.
