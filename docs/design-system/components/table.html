Component · Data display

Table

Tables are for operators comparing records across the same columns: the audit log, metrics by week, caterers by status. Customers and caterers see rows, not tables.

WCAG 2.2 AAStatus: stableNative <table>.table

Overview

Use a table when people read across a row and down a column at once: who did what, to which caterer, when and why (the operator audit log), or a number per week (the metrics page). Every table has a caption, header cells with scope, and sits in .table-wrap so it scrolls sideways inside itself on phones.

  • Default: text records such as the audit log and the privacy notice's cookie and retention tables.
  • Numeric: right-aligned tabular figures in .num cells, row headers on the left (metrics, "Caterers by status").
  • Dense (.table--dense): half the vertical padding, for long operator lists.
  • Sortable: header buttons with aria-sort.
  • With row actions: small buttons in a last column (.row-actions), revealed on row hover or focus on desktop and always visible on touch.

Don't use a table for things people scan one at a time, each with a photo or a status: enquiries are inbox rows, the operator queue is queue items, cuisines and operators are settings rows, one caterer's facts are a description list. Don't use a table for layout.

Anatomy

  1. Caption<caption>: --text-label, muted, left. Usually visually hidden because a heading above says the same.
  2. Wrapper.table-wrap: 1px top rule, --color-bg-surface, scrolls sideways.
  3. Column headerth scope="col": muted label, one line, sticky to the top of the wrapper.
  4. Row headerth scope="row": names the row ("Published", "Week of 31 Aug").
  5. Numeric cell.num: right-aligned, tabular figures.
  6. Row separator1px --color-border-default under each row except the last; no zebra stripes, no vertical lines.

Responsive behaviour

  • XS and SM (below 48rem): tables keep their columns and scroll sideways inside .table-wrap; the page itself never scrolls sideways. The wrapper is a focusable region (tabindex="0", labelled by the caption) whenever it can overflow, so it can be scrolled with arrow keys. Narrow two-column tables (metrics, privacy) fit at 320px and need no region.
  • Row actions are always visible on touch screens (@media (hover: none)), and their small buttons grow to 44px below 48rem.
  • MD and up: the audit log fits from about 62rem; column headers stay on one line and long cells wrap.
  • Long tables paginate below ("Showing 41–60 of 1,284" and pagination) rather than loading endlessly.
  • Tables are not turned into cards on phones: operators compare across rows, and the console is mainly a desktop tool.

Theming

The table reads --color-bg-surface (wrapper and sticky header), --color-border-default (rules), --color-fg-muted (headers, caption), --color-fg-default (cells), --color-bg-subtle (hover), --color-accent-subtle (selected) and --color-fg-subtle (.na). No component tokens. In dark, rules drop to stone-750 and hover to stone-800; selected stays a deep pepper tint so it still reads as "you are here" without a border.

Accessibility

Role and pattern

A native <table> with <caption>, <thead> and th scope (APG Table; sortable headers follow the sortable table example). It is not a grid: Tab moves between the links and buttons inside, not between cells. Dates are <time datetime> in UTC, shown in Toronto time.

Keyboard

KeyAction
TabFocuses the scroll region (when it can overflow), then sort buttons, links and row actions in reading order.
← / →With the region focused, scroll the table sideways.
Enter, SpaceOn a sort button, sorts by that column (descending first for dates and counts) and updates aria-sort.

Focus

Row actions become visible as soon as anything in the row has focus (:focus-within), so keyboard users never tab onto an invisible button. The sticky header must not cover a focused cell when the wrapper scrolls vertically.

Labelling

Every table has a caption, visually hidden when a heading says the same ("Caterers by status"). Row-action buttons name their row ("Open Pelau House"), and the actions column has a hidden header ("Actions"). The empty marker is aria-hidden with a hidden word ("No change") so screen readers don't say "em dash".

Motion

Row actions fade in over --duration-fast; nothing else moves. Skeleton shimmer stops under reduced motion.

Touch

Below 48rem row actions are always shown and their small buttons are 44px tall; sort buttons get the header's full cell height. Horizontal scrolling uses the native swipe.

Content

  • Column headers are one or two words in sentence case: "When", "Operator", "Before → after".
  • Times relative to today when recent ("Today, 9:12 a.m."), otherwise "Fri 9 Oct, 4:30 p.m."; the result line says "times in Toronto".
  • Numbers: thousands separators ("22,670"), percentages without a space ("82%"), money as "$2,600".
  • Name caterers and cuisines in full ("Trinidadian & Tobagonian"); put IDs (cat_0e6d21) under the name in muted text, never as the only identifier.
  • An empty cell is a muted dash with a hidden word, not "N/A" or "null".

Drift fixed during extraction:

  • The audit log wrote empty "Before → after" cells as a bare "—", which screen readers read as "em dash"; the system uses .na with a hidden word.
  • .table th styles every th as a column header: row headers in the metrics and privacy tables become muted, sticky and unwrappable ("Food handler certificate files" forces sideways scrolling at 320px). A CSS change scopes those rules to thead th.
  • Visually hidden text inside a wide table (a hidden "Actions" header, "No change") is absolutely positioned against the page, not the scrolling wrapper, so it widened the whole page at 320px. The examples here set position: relative on .table-wrap; a CSS change makes that the default.
  • Sortable headers, dense tables, row actions, selected rows and .na come from the kit; no mock uses them yet.
