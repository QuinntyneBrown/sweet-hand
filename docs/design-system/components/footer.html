Footer

The footer closes every page with the wordmark, one line about who Sweet Hand is for, and a few quiet links. It has no band, border or background: it is just text on the canvas.

Overview

Every page in the mocks ends with .site-footer, including system pages such as 404 and maintenance. It holds what people look for last: what Sweet Hand is, how to join as a caterer, and the privacy and terms pages. Three audiences get three link sets; the layout never changes.

  • Public (listing, caterer page, inbox, auth, legal pages): "Caribbean caterers in Toronto and the GTA." with About · Cater with us · Privacy · Terms.
  • Caterer dashboard: the same line, but About · Privacy · Terms. A signed-in caterer does not need to be asked to cater with us.
  • Operator console: "Operator console. Every action is written to the audit log." with Privacy · Terms. The line is a standing reminder, not decoration.
  • Legacy .footer: a bordered bar from the base kit. No Sweet Hand screen uses it; it is kept for parity only. Don't use it.

The footer is not navigation for the task at hand: account actions live in the account menu, sections in the site header or side navigation.

Anatomy

  1. Wordmark.site-footer__brand strong: "Sweet Hand" in --text-h4, ink. Plain text, not a link; the header wordmark already goes home.
  2. LineOne sentence, muted, max 22rem wide so it wraps before the links.
  3. Footer navigation<nav aria-label="Footer"> with a list of links, 44px tall, --space-6 apart.
  4. ContainerSame max width and side margin as the header (--layout-container-max, --layout-margin); --space-24 above, --space-10 padding plus the bottom safe area.

Sizes

The footer has one size. Its spacing comes from the layout tokens, which grow with the viewport (the side margin is 16px on phones and 80px from 75rem), so it never needs a size modifier.

States

Only the links have states. Hover and focus are forced with data-state; current uses aria-current="page".

  • Current: on the About, Privacy and Terms pages the matching footer link takes aria-current="page". The stylesheet does not style it yet, so it looks like the default; ink at medium weight is proposed (see Sources).
  • Loading, empty, error: none. The footer renders with the page shell even when the main content fails (pages/server-error/default), so people always have a way to the privacy page.

Responsive behaviour

The footer has no breakpoints of its own: it is a wrapping flex row, so the width decides.

At phone width (360px here) the line stacks above the links, which wrap two or three to a row.
  • XS and SM: brand above links; links wrap with --space-6 between them. The bottom padding adds env(safe-area-inset-bottom) so the last row clears the home indicator.
  • MD and up: brand on the left, links on the right, top-aligned (justify-content: space-between).
  • Caterer page XS to MD: the sticky enquiry bar covers the bottom of the screen, so main.has-sticky-cta pads the page and the footer is never hidden under it (WCAG 2.4.11).
  • From 90rem the footer stops growing and centres with the header (--layout-container-max).

Theming

No component tokens. The footer reads --color-fg-muted for the line and links, --color-fg-default for the wordmark and hover, and sits on the page canvas with no surface of its own. In dark the canvas is near-black stone and the muted text flips to a light stone. Because it has no background, a theme never needs a footer override.

Accessibility

Role and pattern

A top-level <footer> outside <main>, so it is the page's contentinfo landmark (APG contentinfo landmark). Links sit in <nav aria-label="Footer">, distinct from the header's "Primary".

Keyboard

KeyAction
Tab / Shift+TabReaches the footer links last, after pagination and the page content.
EnterFollows the link.

Focus

The shared pepper ring wraps each 44px link. The footer is never covered by a sticky bar, so a focused link is always fully visible.

Labelling

Link text is the destination ("Privacy", "Terms"). The wordmark is plain text, so it is not announced as a second home link.

Contrast

Line and links on page
Wordmark and hovered link

Motion

None. Hover changes colour and underline instantly.

Touch

Each link is 44px tall (--target-comfortable) with 24px between neighbours in a row; wrapped rows touch vertically, but each target is already 44px, so the spacing exception in WCAG 2.5.8 applies and the L2-065.1 gap is met horizontally.

Content

  • The line is one sentence that says who it is for: "Caribbean caterers in Toronto and the GTA." Don't add a slogan or the founding story; About has that.
  • Links are one or two words in sentence case: "About", "Cater with us", "Privacy", "Terms". "Cater with us" invites caterers; it is not "For business" or "Partners".
  • No copyright line, social icons, newsletter form or app badges. None are in the requirements, and each would add text the brand avoids.
  • Operators always see the audit reminder in the line.
