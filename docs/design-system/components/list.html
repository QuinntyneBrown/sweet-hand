List rows

Most of Sweet Hand's settings and records are rows: a title, a quiet line under it, an action at the end, and a hairline between. Four row families share that shape.

Overview

A list row shows one thing per line, readable on its own: a device, a cuisine, an operator, a dish, a breach record. Rows are flat: no card, no shadow, just a 1px rule underneath, in line with Sweet Hand's surfaces. Pick the family by what the row holds:

  • List (.list, .list__item): a compact title-and-meta row with an optional trailing control. The account page's device list (.device-list) is the product use: "Safari on iPhone · Last active today, 8:15 a.m." with "Sign out".
  • Settings rows (.admin-list, .admin-row): larger titles for operator settings: cuisines with their caterer count and "Retire", operators with an avatar and "Deactivate".
  • Editable rows (.edit-list, .edit-row): a caterer's dishes in page order, each with move up, move down, edit and remove icon buttons (the menu manager).
  • Breach records (.breach-list, .breach): tall, read-only records in the privacy breach register, each a heading, a date line and a key-value list.

Use an inbox row for conversations, a queue item for operator review work, a table when people compare columns, a dish for the public menu and a caterer card for browsing.

Anatomy

  1. Leading visual (optional)A 44px avatar for people; nothing for things. aria-hidden when the name follows.
  2. Title__title: the row's name. --text-body-lg medium in settings rows, --text-label in a list; can carry a badge ("You", "New").
  3. Meta__meta: facts joined by middle dots in --text-body-sm, --color-fg-muted.
  4. Actions (optional)__actions: small ghost buttons or 44px icon buttons, pushed to the end; they wrap under the body when space runs out.
  5. Row rule1px --color-border-default under each row; the list adds one on top (except .list, which drops the last row's rule).

Both themes

  • Grenadian4 published caterers
  • Grenadian4 published caterers
  • Loading: skeleton rows of the same family (.admin-row--skeleton, .edit-row--skeleton), each aria-hidden; the list gets aria-busy="true" and a loading label, and a visually hidden role="status" line says "Loading cuisines".
  • Read-only (profile-menu/read-only, while a profile waits for review): editable rows drop their actions and a status alert above explains why.
  • Full (profile-menu/full): rows are unchanged; the add button above is disabled with the reason visible ("You can list up to 50 dishes. Remove one to add another.").
  • Selected: aria-selected="true" on a .list__item is only valid inside role="listbox" (like the area suggestions in the search dialog); a navigation list marks the open item with aria-current. Both use the pepper tint.
  • Empty and error: the list is replaced by an empty state ("What do you cook best?", "We couldn't load your menu").

Responsive behaviour

  • XS (below 36rem): editable rows stack: dish details, then the four icon buttons on their own line. Settings rows wrap their actions under the body when the title and meta need the width (the body's flex basis is --space-32).
  • SM and up (36rem+): editable rows become two columns, details and actions side by side.
  • Below 48rem: small row buttons ("Sign out", "Retire", "Deactivate") grow to 44px tall (L2-065.1); icon buttons are 44px at every width. From 48rem the small buttons return to 36px.
  • Breach records' key-value pairs stack below 36rem and sit in a 12rem label column above it.
  • Long titles wrap (overflow-wrap: anywhere); nothing truncates, so "Dominican (Dominican Republic)" and long dish names stay readable.

Theming

Rows read --color-border-default (rules), --color-fg-default (titles), --color-fg-muted (meta), --color-bg-subtle (interactive hover) and --color-accent-subtle (selected). Rows have no background of their own, so they sit on whatever surface holds them: the canvas on pages, the raised surface in a dialog. In dark the rules drop to stone-750; badges and status labels bring their own tokens.

Accessibility

Role and pattern

Native lists: <ul>, or <ol> when order is meaningful (dishes). Each list has an aria-label that says what and in what order ("Cuisines, A to Z", "Dishes, in the order they appear on your page", "Recorded breaches, newest first"), so the list announcement gives context and count. No ARIA list roles are added; an interactive row is a real link or button (APG Listbox only for a true selection list).

Keyboard

KeyAction
TabMoves through each row's controls in order: up, down, edit, remove; then the next row.
Enter, SpaceActivates the focused control. Moving a dish keeps focus on the same button in its new position, and a status line says "Doubles moved to position 4 of 12".

Focus

After removing a row (confirmed in a dialog), focus goes to the next row's first control, or to the list heading if it was the last. A disabled "Move up" on the first row is skipped by Tab, which is fine because its reason is obvious from position.

Labelling

Every row action names its row: "Move Chicken pelau up", "Retire Belizean", "Deactivate Tomas Reyes", "Sign out Safari on iPhone". The aria-label starts with the visible word, so voice control ("click Retire") still works (WCAG 2.5.3). Avatars are aria-hidden beside the name.

Motion

Interactive rows fill over --duration-fast. Reordering does not animate. Skeleton shimmer stops under reduced motion.

Touch

Icon buttons are 44px with no gap between them, which is acceptable because each meets the full target size. Small text buttons grow to 44px below 48rem. Whole-row links are at least 44px tall.

Content

  • Titles are the thing's own name: "Safari on iPhone", "Barbadian (Bajan)", "Tomas Reyes", "Chicken pelau". Spell dishes as the caterer does.
  • Meta lines join two or three facts with middle dots, most useful first: "Operator · Security key · Last active today, 8:15 a.m.".
  • Counts use the noun: "1 published caterer", "No published caterers", not "0".
  • Row actions are one verb: "Sign out", "Retire", "Deactivate". The dialog they open names the consequence.
  • Badges in titles are one word: "You", "New".
