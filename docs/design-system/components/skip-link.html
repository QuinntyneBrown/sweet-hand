Skip link

The skip link is the first thing a keyboard user reaches on every Sweet Hand page. It stays out of sight until focused, then jumps straight past the header to the main content.

WCAG 2.2 AAStatus: stableWCAG 2.4.1 Bypass blocks.skip-link

Overview

Every page starts with <a class="skip-link" href="#main">Skip to main content</a> as the first element in <body>. It sits above the top of the viewport until it receives keyboard focus, then slides into view at the top left, over the site header. Activating it moves focus to <main id="main">, so the next Tab lands on the first link or field of the page rather than the wordmark, three nav links, search and the avatar again.

  • Use it on every page template: public pages, the caterer dashboard, the operator console, auth and system pages (404, offline, maintenance).
  • Don't add a second skip link ("Skip to filters", "Skip to footer"). Landmarks and headings already let screen-reader users jump; one link is enough for sighted keyboard users.
  • Don't use it as a substitute for focus management: opening a dialog moves focus into the dialog by itself.

Anatomy

  1. ContainerRaised surface (--color-bg-surface-raised), --radius-md, --shadow-3, padding --space-2 --space-4; layer --z-tooltip, above everything.
  2. Label"Skip to main content" in body text, --color-fg-default, no underline; it is the accessible name.
  3. Target<main id="main">, the page's one main landmark.

Sizes

The skip link has one size: body text with --space-2 by --space-4 padding, about 40px tall. It appears only on keyboard focus, so it does not need size variants.

States

The only state change is focus: :focus-visible in the product, data-state="focus" here. Hover, active and visited look the same as focused.

Responsive behaviour

  • Identical at every breakpoint: left: var(--space-4), top: var(--space-4) when focused. At 320px the label fits on one line with room to spare.
  • It overlaps the site header while focused; that is intended and lasts only until focus moves on. The header's height (--layout-topbar-height, 4/5/6rem) does not affect it.
  • On phones with a hardware keyboard or switch access it works the same; it never appears on touch alone because touch does not trigger :focus-visible.
  • Page scroll padding (scroll-padding-top: var(--layout-topbar-height)) keeps the target's first line from sitting under anything after the jump.

Theming

The skip link reads --color-bg-surface-raised, --color-fg-default and --shadow-3, like a menu or popover, because it floats over the header. In dark the raised surface is --palette-stone-850, a step lighter than the canvas, and the stronger dark shadow keeps it separate from the header. No component tokens.

Accessibility

Role and pattern

A plain in-page link (<a href="#main">), the standard technique for WCAG 2.4.1 Bypass Blocks. Browsers move the sequential focus starting point to the target, so <main> needs no tabindex.

Keyboard

KeyAction
Tab (first press on a page)Focuses the skip link and shows it.
EnterJumps to #main; the next Tab reaches the first control in the main content.
Tab again without EnterHides it and continues to the wordmark.

Focus

It must be the first focusable element: nothing (not even a cookie or site banner) comes before it in the DOM. Its own focus ring is the shared 2px pepper ring with a 3px offset.

Labelling

The visible text is the name. Don't add aria-label or title.

Contrast

Label on raised surface
Focus ring on raised surface
Focus ring on the header (canvas)

Motion

It slides down over --duration-fast (120ms). Reduced motion makes it appear in place.

Touch

Not a touch feature. It is about 40px tall; raising it to --target-comfortable (44px) is proposed so it matches every other control.

Content

  • Exactly "Skip to main content", in sentence case, on every product page. The design-system site uses "Skip to content"; that is the docs chrome, not the product.
  • No arrows, icons or "Click here".
  • Translate it with the page when other languages arrive; it is real copy, not a technical string.
