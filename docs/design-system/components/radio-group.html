Radio group

A radio group asks for exactly one answer: the reason for a report, an operator's role, a caterer's primary cuisine. All the options stay visible, so people can compare them before choosing.

Overview

A radio group is a <fieldset> of native <input type="radio"> elements that share a name. Each option is a <label class="choice">, the same row as the checkbox, with a round box. Choosing one clears the others.

  • Use it for 2 to 6 mutually exclusive options that each need a word of explanation: report reasons ("Food safety concern · Something that could make people ill"), the operator role, a moderation decision, the breach risk level.
  • Use it for "which one is primary" when the candidates are few. The primary cuisine is a radio group because a caterer has at most 5 cuisines.
  • Use a select when there are more than about 6 options or they are well known and need no explanation: primary area (up to 30 areas), occasion, event area in the enquiry form.
  • Use checkboxes when more than one answer is allowed, and a switch for a single on/off setting.
  • Use the segmented control to switch views or filters on a page (Inbox "All · Open · Replied"); that is navigation, not a form answer.

The selected dot fills with pepper red (--color-accent), the brand's "selected" colour, exactly like a checked checkbox.

Anatomy

  1. LegendThe question, in --text-label. Required: it names the group for screen readers.
  2. Radio20px circle, 1px --color-border-strong; selected: pepper fill with an 8px dot in --color-fg-on-accent.
  3. LabelThe option, in .choice__text; the accessible name.
  4. Description (optional)A <small> in --color-fg-muted that says what the option means or does.

Variants

Vertical (default)

Options stack, one per row. This is the only layout the mocks use, and it is the right one whenever options have descriptions or long labels.

Role
From dialogs/add-operator. Preselect the least-privileged role; the mock left both empty.
HTML
<fieldset>
  <legend>Role</legend>
  <label class="choice"><input type="radio" name="role" value="operator" checked>
    <span class="choice__text">Operator<small>Reviews profiles, reviews and reports</small></span></label>
  <label class="choice"><input type="radio" name="role" value="admin">
    <span class="choice__text">Admin<small>Also manages operators and the full audit log</small></span></label>
</fieldset>

Horizontal

Two or three options with one- or two-word labels and no descriptions may sit on one line in a .cluster. They wrap to separate lines on narrow screens, which keeps the order readable.

Decision
Only when the labels say everything. dialogs/resolve-report keeps the vertical layout because each decision has a consequence line.
HTML
<fieldset><legend>Decision</legend>
  <div class="cluster" style="gap: var(--space-2) var(--space-6);">
    <label class="choice"><input type="radio" name="decision" checked><span class="choice__text">Dismiss</span></label>
    <label class="choice"><input type="radio" name="decision"><span class="choice__text">Take action</span></label>
  </div>
</fieldset>

Card (.choice--card)

Each option gets a bordered, padded box; the selected card's border turns pepper. Use it when an option carries a real consequence that deserves room, such as a breach notification decision. Cards are the one place a form control gets a border: the border is the control's edge, not decoration.

Notification decision
Content from dialogs/record-breach, which uses the plain vertical layout. Cards stack at every width; never put them side by side.
HTML
<label class="choice choice--card"><input type="radio" name="decision" value="report" checked>
  <span class="choice__text">Report to the Privacy Commissioner and notify the people affected<small>…</small></span></label>

Primary pick

Choosing the primary cuisine is a radio group built from the cuisines already ticked above it. Where the choice is shown read-only (the profile under review, the operator's caterer record) the chosen value carries .primary-pick, a small pepper "Primary" label.

Sizes

Radios have one size: a 20px circle beside body text. Emphasis comes from the card layout, never from a bigger circle; the star rating input is a radio group too, but it is its own component (see rating).

States

Hover and focus are forced with data-state; selected, disabled and invalid use the real checked, disabled and aria-invalid attributes. Each cell is its own group so the matrix can show two selected radios at once.

Responsive behaviour

  • Vertical groups and cards are the same at every breakpoint; labels wrap under themselves, never under the circle.
  • Horizontal groups are a wrapping .cluster: at 320px "Take action" drops under "Dismiss" instead of squeezing.
  • Inside the enquiry, report and breach dialogs (full screen below 36rem) groups keep the dialog's padding; cards stretch to the full body width.
  • Phones: like the checkbox, a plain .choice row is about 32px tall; the pending phone rule raises it to 44px (--target-comfortable) for L2-065. Cards already exceed it (16px padding on each side).

Theming

Radios share every token with the checkbox: --color-bg-surface fill, --color-border-strong edge, --color-fg-muted on hover, --color-accent when selected with an --color-fg-on-accent dot, --color-danger-solid ring when invalid. Cards add --color-border-strong and --radius-md, and an inset pepper ring when selected.

In dark, pepper lifts to --palette-pepper-300 and the dot becomes near-black, so the selected radio is still the brightest mark in the group. Re-skin by overriding --color-accent on a wrapper, never by restyling .choice input.

Accessibility

Role and pattern

Native radios in a <fieldset> with a <legend> (APG Radio Group). Browsers supply the roving focus and arrow-key selection for radios that share a name, so no script or role="radiogroup" is needed.

Keyboard

KeyAction
Tab / Shift+TabEnters the group on the selected radio (or the first one if none is selected) and leaves it in one step. The group is a single tab stop.
↓ / →Moves to the next radio and selects it; wraps from last to first.
↑ / ←Moves to the previous radio and selects it; wraps from first to last.
SpaceSelects the focused radio when none is selected yet.

Because arrows change the answer, never run an action on change (no auto-submit, no navigation). A decision in a moderation dialog takes effect only on the dialog's primary button.

Focus

The shared ring circles the radio, not the row or the card. When a dialog opens on a group with an answer already chosen (dialogs/resolve-report defaults to "Dismiss"), autofocus goes on that selected radio.

Labelling

  • The legend is the group name; each label names its option. The description inside .choice__text is read with the option.
  • Help and errors for the whole group go in the fieldset's aria-describedby.
  • The radio that a summary links to needs an id; the others do not.

Motion

Colours transition over --duration-fast; the dot appears without movement. Reduced motion zeroes the duration.

Touch

The whole label row (or the whole card) is the target. Leave at least --space-2 between cards so neighbouring targets are 8px apart.

Content

  • The legend is a noun or a short question: "Reason", "Role", "Decision", "Risk of significant harm", "Primary cuisine".
  • Options are parallel in grammar and start with the distinguishing word: "Inaccurate information", "Inappropriate content", "Fake or spam", "Food safety concern", "Other".
  • Descriptions say what the option means or what happens next, in one line: "Nothing breaks the rules. Any automatic hiding is undone."
  • Put "Other" last and pair it with a details field that becomes required when it is chosen ("Tell us what's wrong").
  • Errors say "Choose a notification decision", "Choose a reason"; never "Please make a selection".
  • Don't preselect an answer that would bias a report; do preselect the safe default in an operator decision (Dismiss) and the least privilege in a role.

The primary cuisine (radios) and primary area (select) answer the same kind of question with different controls; the system keeps both and states the rule (radios up to about 6 options, a select beyond). .choice--card and horizontal groups are in the kit but appear in no mock; they are documented for future use.
