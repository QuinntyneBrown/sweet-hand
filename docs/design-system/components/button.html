Button

Buttons let people do something: send an enquiry, save a dish, approve a profile. One solid ink button per screen tells them what matters most.

Overview

Use a button when activating it changes something: it submits, saves, removes, opens a dialog or starts a process. Use a link when it only goes somewhere, an icon button for a single-glyph action in a header or row, and a menu when one trigger offers several actions.

  • Primary is solid ink (--color-action), like the wordmark. It is the one action the screen exists for: "Send an enquiry", "Approve and publish", "Sign in". Never two per screen.
  • Secondary (the default look) is an outlined pill for everything else that is still an action: "Cancel", "Edit", "Load more".
  • Ghost has no border; it sits in dense places such as row actions, photo-tile moves and the phone browse bar.
  • Link looks like a link but is a button; use it for low-emphasis actions inside text and empty states ("Clear filters").
  • Danger is for destructive or punitive actions and only appears inside a confirmation dialog: "Delete my account", "Suspend caterer", "Remove permanently".

Pepper red is never a button colour. It means "selected / you are here"; an action in pepper would read as a current filter.

Anatomy

  1. Leading icon (optional)1.25em square outline icon, inherits the label colour, aria-hidden="true".
  2. LabelA verb phrase in sentence case; it is the accessible name.
  3. ContainerPill (--radius-full), 1px border, height from --control-height-* (44px by default), padding --space-3/4/6.

Variants

Variants change emphasis, not meaning. Pick by how much attention the action deserves on this screen.

Primary, secondary, ghost, link, danger: highest to lowest emphasis; danger only inside a confirmation.
HTML
<button class="btn btn--primary" type="button">Send an enquiry</button>
<button class="btn" type="button">Cancel</button>
<button class="btn btn--ghost" type="button">Edit</button>
<button class="btn btn--link" type="button">Clear filters</button>
<button class="btn btn--danger" type="button">Suspend caterer</button>

With icons, icon-only, block and wrapping

Icon-only buttons carry aria-label naming the object; .btn--block fills its container (phone CTAs); .btn--wrap lets a long label wrap left-aligned.

Sizes

Medium (44px) is the default, so every button already meets the phone target (L2-065). Small (36px, from 48rem) lives in rows (edit, remove, move) with at least 8px to the next target, and grows to 44px on phones (L2-065.1); large (52px) is for the enquiry call to action, auth screens and system pages.

Heights --control-height-sm/md/lg; padding --space-3/4/6; label --font-size-sm/md/lg.

States

Every variant has the same six states. Pointer and focus states are forced here with data-state; real pages get them from :hover, :focus-visible, :active, disabled and aria-busy.

Both themes

  • Loading keeps the button's width and label (the label is hidden visually, not changed), shows a spinner in the label colour, sets aria-busy="true" and aria-disabled="true", and ignores clicks. Progress text ("Sending your enquiry…") goes in the dialog's live region.
  • Disabled uses the native attribute at 50% opacity. Prefer an enabled button that explains the problem on activation (the form summary does this); disable only when the reason is visible, such as "Upload photo" at 30 of 30 photos.
  • Pressed (toggle buttons) uses aria-pressed; see button group. Expanded (a trigger for a dropdown) uses aria-expanded; see filter trigger.

Responsive behaviour

  • Below 48rem the primary call to action on a page becomes full width (.btn--block) in the sticky bar or form; secondary actions stack beneath it.
  • Dialog footers keep buttons on one row and wrap when they do not fit; the primary stays last (rightmost, or bottom when wrapped). The phone filter sheet stretches both buttons (.sheet__footer .btn).
  • .btn never exceeds its container (max-width: 100%). A label that would overflow at 320px gets .btn--wrap or a shorter verb phrase; it never truncates.
  • Sizes do not change by breakpoint: a 44px button is comfortable on every device.

Theming

The button reads semantic tokens through five component tokens (--btn-bg, --btn-fg, --btn-border, --btn-bg-hover, --btn-bg-active) that each variant overrides. A theme changes the semantic tokens; a re-skin overrides the component tokens; neither edits .btn.

/* An occasion campaign could re-skin the primary without touching .btn */
[data-theme="carnival"] .btn--primary { --btn-bg: var(--color-action); --btn-fg: var(--color-fg-on-action); }

In dark the ink flips: primary becomes light stone (--palette-stone-100) with near-black text, so it still reads as "the" button; danger uses --palette-sorrel-300 with dark text. Both stay above 7:1.

Accessibility

Role and pattern

Native <button type="button">, or type="submit" inside a form (APG Button). A link styled as a button stays an <a href> ("Browse caterers" on the 404 page). Buttons that open a dialog add aria-haspopup="dialog".

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order.
Enter, SpaceActivates. Space fires on key up, so a mis-press can be cancelled by moving away.
EscNo effect on the button; in a dialog it closes the dialog, which is the same as Cancel.

Focus

The shared ring (2px --color-focus-ring, 3px offset) shows on :focus-visible only. The offset gap shows the surface behind, so the pepper ring stays at least 3:1 against both the ink button and the page.

Labelling

The visible label is the accessible name. Icon-only buttons name the action and object: aria-label="Remove Doubles", not "Remove". A busy button keeps its name; it does not swap to "Saving…".

Motion

Background, border and shadow transition over --duration-fast (120ms); the active state nudges 1px down. Reduced motion zeroes the duration and removes the nudge. The busy spinner keeps turning because it reports status.

Touch

Medium (44px) and large (52px) meet the 44px comfortable target. Small is 36px only from 48rem, inside rows with 8px between buttons; below 48rem it grows to 44px like every other target (L2-065.1).

Content

  • Verb phrases in sentence case, Canadian English: "Send an enquiry", "Approve and publish", "Add a dish", "Try again". Never "OK", "Submit", "Yes" or "Click here".
  • Name the object when context does not: "Remove photo" in a row, "Remove permanently" in the confirmation.
  • Destructive labels say what is lost: "Delete my account", "Decline enquiry", not "Confirm".
  • Three words where possible; a label that wraps at 360px is too long.
  • Cancel is always "Cancel"; the dismiss of a successful dialog is "Done".
