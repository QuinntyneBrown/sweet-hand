Component · Data display

Bar chart

The operator metrics page shows each measure as a small column chart: one ink bar per week, a total beside the title, and the same numbers one tap away as a table. Pure CSS, no chart library.

Overview

Bar charts live on one screen, admin metrics, where Leah and Tomas check how Sweet Hand is doing over a date range: enquiries, the share replied within 48 hours, listing and caterer page visits, unique visitors. Each measure gets a chart card with its title, its total for the range, the bars, a date axis and a "Show as a table" disclosure.

  • Use a bar chart to show one measure changing over equal periods (days, weeks, months), where the shape matters more than exact values.
  • Use a stat for the single headline figure; the metrics page puts four stats above the charts.
  • Use a table when people need exact values or compare several measures; every chart already contains one.
  • Don't use a bar chart for parts of a whole, for more than one series, or on customer and caterer screens. Caterers see counts (stats), not charts.

Bars are ink (--color-fg-default), like the primary button and the wordmark. Pepper (.bar-chart__bar--accent) marks one bar only: the current, still-running period — "you are here" on the time axis.

Anatomy

  1. TitleAn <h3> naming the measure; it labels the card (aria-labelledby).
  2. Total.chart-card__total: the range total or average, --text-h3, tabular numerals.
  3. Bar.bar-chart__bar: height var(--value) (a percentage of the plot), ink, rounded top corners (--radius-xs).
  4. Current period (optional)--accent: the running week in pepper.
  5. BaselineThe plot's bottom border, --color-border-strong; the plot is 10rem tall. Bars always start at zero.
  6. Axis.bar-chart__axis: one caption per bar, --color-fg-subtle, hidden from assistive technology (the image label and table carry the dates).
  7. Table alternative<details> "Show as a table" with a real .table: every value, exact.

Sizes

Bar charts have one size: a 10rem plot that fills its card's width. Bar width follows from the number of periods (bars share the width with --space-2 gaps), not from a size option.

States

The chart itself isn't interactive; its <summary> is. The states that matter are the data states the metrics page mocks: default, partial (one chart failed), empty range, error, loading and invalid range.

  • Partial (pages/admin-metrics/partial): a chart whose data failed keeps its title and drops its total; a danger alert ("This chart didn’t load · The other figures are up to date") with "Try again" replaces the bars. The matching stat shows "Not loaded", and "Export CSV" is disabled until everything has loaded.
  • Empty (pages/admin-metrics/empty): a range with no data replaces all charts with one empty state — "No activity in this range · Sweet Hand started counting visits and enquiries on 3 Aug 2026" — and one action, "Show the last 6 weeks". Never draw a row of zero-height bars.
  • Error (pages/admin-metrics/error): the metrics service failed; an error empty state ("We couldn’t load metrics") with "Try again" and a reference id. The date range is kept.
  • Loading: each card shows a title skeleton, a total skeleton and a rectangle the height of plot plus axis; a single visually hidden status says "Loading metrics".
  • Invalid range (pages/admin-metrics/invalid): the form shows "Choose a range of 24 months or less"; the charts keep showing the last valid range.

Responsive behaviour

  • Below lg (62rem): one chart per row, full width of the work area. Six weekly bars are about 2.5rem wide each at 320px.
  • lg (62rem) and up: .chart-grid is two columns with a --space-12 gap; card heads stay on one line (title left, total right) and wrap only if the title is very long.
  • Many periods: with "Show by: Day" a six-week range is 41 bars, and 40 gaps of 8px don't fit a phone. Up to 14 bars per chart on phones and 31 on wider screens; beyond that, aggregate (week or month) or open the table by default. A tighter-gap rule for dense charts is proposed.
  • Axis labels never wrap; a label that doesn't fit its bar's width is clipped, which is why every value is also in the image label and the table.

Theming

Bars read --color-fg-default (ink) and --color-accent (current period); the baseline --color-border-strong; the axis --color-fg-subtle; the card divider --color-border-default. No component tokens and no chart palette: Sweet Hand charts have one series. In dark the bars become stone-100 and the accent pepper-300, so the bars stay the most contrasting thing in the card in both themes.

Accessibility

Role and pattern

Each card is a <section aria-labelledby> named by its <h3>, so screen-reader users can jump between charts by heading or region. The plot is role="img" with an aria-label that lists every period and value ("Enquiries by week. 31 Aug: 8, 7 Sep: 11, …"); the bars inside are empty spans. The axis is aria-hidden="true". The <details> table is the full equivalent (W3C complex images), with a caption and row headers.

Keyboard

KeyAction
TabMoves from chart to chart via each "Show as a table" summary (and "Try again" in a failed chart). Bars are not focusable.
Enter, SpaceOpens or closes the table.

Focus

The summary takes the shared focus ring; it is at least 44px tall (--target-comfortable), so the ring has room.

Labelling

The image label starts with the measure and the period unit ("by week"), then every value; mark a running period "so far". The summary reads "Show as a table"; the table caption repeats the chart title ("Enquiries by week").

Motion

Bars don't grow or animate in. A changed range swaps the chart in place.

Touch

The only target is the 44px summary row (and "Try again" when a chart failed).

Content

  • Titles name the measure in sentence case, units spelled out: "Replied within 48 hours", "Caterer page visits".
  • Totals match the stat above when both exist (71 enquiries, 39,700 visits); averages say "avg" ("2,578 avg").
  • Axis labels are short dates, "31 Aug"; table rows say "Week of 31 Aug". The page subtitle gives the range and time zone: "31 Aug – 10 Oct 2026 · by week · Toronto time".
  • Numbers use comma thousands and "%" without a space.
