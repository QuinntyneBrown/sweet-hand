Component · Data display

Dish

One item on a caterer's menu: the dish name as the caterer spells it, an optional price in Canadian dollars, a short line about it, and dietary and allergen tags as structured data. No photo, no card, just a quiet ruled list.

Overview

The menu is how a customer decides whether a caterer cooks what they want: curry goat, buss up shut, black cake. A dish is a row of text under the caterer's round photos, never a card. Only the name is required; price, description and tags are each optional, and a dish without them still reads cleanly (caterer/edge lists "Goat water" and "Conkies" with nothing else).

  • Public menu (.dish-list of .dish): the caterer page's Menu section. The first 12 dishes show; "Show all 18 dishes" expands the list in place.
  • Menu manager (.edit-list of .edit-row holding the same .dish__* parts): the caterer's dashboard, with move up, move down, edit and remove beside each dish. Editing opens dialogs/dish; there are no inline forms.

Use a dish for menu items only. Food photos are photos and photo tiles; a caterer's cuisines and service areas are tags and description lists; the dietary and allergen labels inside a dish are tags, documented there in full.

Anatomy

  1. Name.dish__name, an h3 under the Menu h2; --text-h4 at --font-size-lg. Wraps anywhere; never truncates.
  2. Price (optional).dish__price: CAD, --text-body-sm, muted, tabular figures, never wraps inside itself.
  3. Description (optional).dish__desc: one short line, --text-body-sm, muted.
  4. Dietary tags.tags of .tag: Vegan, Vegetarian, Halal, Gluten-free, Dairy-free, Spicy.
  5. Allergen tag.tag--allergen: "Contains nuts", "Contains shellfish" in the warning pair, so allergens stand out from preferences.
  6. Rule1px --color-border-default under each dish; --space-5 above and below. No card, no shadow.

Sizes

A dish has one size. The list changes columns by breakpoint (see Responsive) but the type, spacing and tags never shrink.

Responsive behaviour

  • Below 48rem: one column, with a rule above the first dish (border-top on the list) so the menu reads as a ruled list under the "Menu" heading.
  • 48rem and up: two equal columns with a --space-12 gutter; the top rule goes, each dish keeps its bottom rule. Order runs left to right, then down.
  • Name and price share a line while the name has at least 12rem; otherwise the price wraps below. At 320px "From $1,250 per 50 guests" sits under the name, never squeezed beside it.
  • Menu manager: actions below the dish on phones, to the right from 36rem (.edit-row grid). Each action is 44px, so four fit in 11rem with 4px gaps.
  • The dashboard's listing-card preview (.preview-pane) only appears from 75rem; it never shows dishes.

Theming

No component tokens. The name reads --color-fg-default; price and description read --color-fg-muted; the rule is --color-border-default. Dietary tags use the neutral tag look; allergen tags use the warning trio (--color-warning-bg, --color-warning-fg, --color-warning-border). In dark the warning pair becomes a deep amber surface with light amber text, and still clears 4.5:1.

Pepper red never marks a dish, a price or a "spicy" tag: red means "selected" on Sweet Hand, and a red dish would look chosen. Spice is a word, not a colour.

Accessibility

Role and pattern

A plain list (<ul class="dish-list">) of list items; on the public page each name is an h3 under the "Menu" h2, so screen-reader users can jump dish to dish. Tags are a nested <ul>. In the manager the list is an <ol aria-label="Dishes, in the order they appear on your page"> because order is the point. The expand toggle follows the APG Disclosure pattern.

Keyboard

KeyAction
TabPublic: dishes are not focusable; Tab goes to "Show all 18 dishes". Manager: move up, move down, edit, remove for each dish in order.
Enter, SpaceOn a move button, moves the dish one place; focus follows the dish to its new row and stays on the same button. On edit/remove, opens the dialog.
EscIn the dish or remove dialog, closes it and returns focus to the button that opened it.

Focus

The shared 2px pepper ring on each 44px icon button. A move that reaches the top or bottom keeps focus on the now-unavailable button, which is why it uses aria-disabled="true" rather than disabled (a disabled button drops focus to the page).

Labelling

Every action names the dish: "Move Doubles up", "Edit Doubles", "Remove Doubles". After a move a polite live region says "Doubles moved to position 4 of 18". Allergen tags are self-describing ("Contains shellfish"); never shorten to an icon or "Shellfish".

Motion

Expanding the list and moving a dish are instant; no animation reorders rows. Skeletons shimmer and stop under reduced motion.

Touch

Manager actions are 44px icon buttons with 4px between them; the targets do not overlap and clear WCAG 2.5.8. Public dishes have no targets of their own.

Content

  • Names are the caterer's. Spell dishes as the caterer and their community do: "Buss up shut", "Pholourie", "Paw paw chow", "Saltfish buljol", "Curry channa and aloo". Sentence case, no translation, no "Caribbean" catch-all.
  • Prices are CAD with a unit. "From $16 per person", "$3 each, 40 minimum", "$65 per cake", "$14 per litre", "From $1,250 per 50 guests". Use "From" when the price depends on the order; no cents unless they matter; no "CAD" suffix (the whole site is Canadian dollars); no tax.
  • Descriptions are one line of what is in it or how it is made: "Slow-cooked with scotch bonnet." Not a story, not a sales pitch.
  • Tags are fixed words from the dietary list (Vegan, Vegetarian, Halal, Gluten-free, Dairy-free, Spicy) and allergen list ("Contains nuts", "Contains shellfish"). They are the caterer's own statement; never write "certified", "safe for" or "allergen-free".
  • The section head gives the total: "18 dishes"; the toggle names it: "Show all 18 dishes" / "Show fewer dishes".

Drift fixed during extraction:

  • "Show all 18 dishes" had no aria-controls in caterer/default (it did in more-dishes); both now point at #dish-list.
  • First/last move buttons used disabled, which drops focus after a move to the end; they now use aria-disabled="true".
  • Extraction regression: .dish__name { flex: 1 1 12rem } is global in components.css, but inside .edit-row the row is a column, so the basis becomes a 12rem height and opens a gap under every name in the menu manager. The mocks scoped it to .dish-list .dish__name. Fix proposed (.edit-row .dish__name { flex: none; }); the manager examples on this page carry it inline until then.
  • Public loading skeletons sized their bars with inline style="width: 50%"/80%, while the manager had .edit-row--skeleton; a matching .dish--skeleton is proposed so the public list drops the inline widths.
