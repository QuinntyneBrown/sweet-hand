Component · Data display

Inbox row

One row per enquiry: who it is with, when it last moved, the event in a few words and where it stands. Customers see the caterer's food photo; caterers see the customer's initials.

Overview

The inbox row is how both sides of Sweet Hand find a conversation. Each row is one link to the enquiry's thread, laid out on a two-line grid: picture, name and time on the first line, event summary and status on the second. Rows stack in .inbox-list with hairline rules between them.

  • Customer row (pages/inbox): the caterer's round food photo and name; Marcia sees Pelau House, Sugar Dumplin, Demerara Kitchen, Ti Kay.
  • Caterer row (pages/dashboard-enquiries): the customer's initials in an avatar, plus the occasion in the summary; a customer who deleted their account shows a person icon and "Former Sweet Hand user".
  • Unread (.inbox-row--unread): pepper dot, bold name, darker summary, and a hidden "Unread." for screen readers.
  • Current (aria-current): the row whose thread is open beside the list from 62rem.

Use a queue item for operator review work (it shows wait time), a list row for settings, and a message for the conversation itself.

Anatomy

  1. Picture48px round photo (customer view) or avatar (caterer view), spanning both lines. Empty alt: the name follows.
  2. Unread dot.unread-dot: 10px pepper circle, aria-hidden, with a visually hidden "Unread." after it.
  3. Name.inbox-row__name: --text-body medium (bold when unread), one line with an ellipsis.
  4. Time.inbox-row__time: last activity in --text-caption, --color-fg-subtle, right-aligned.
  5. Summary.inbox-row__meta: event date, guests and (caterer view) occasion, joined by middle dots; one line.
  6. Status.inbox-row__status plus a status label: Open, Replied, Declined, Closed. Word and shape, never colour alone.

Sizes

The inbox row has one size: a 48px picture, --space-4 vertical padding and two text lines, about 81px tall, at every breakpoint. The operator queue item is the larger cousin (56px picture).

  • Unread is three signals at once (dot, bold name, darker summary) plus hidden text, so it never relies on the pepper dot alone (WCAG 1.4.1).
  • Current uses a neutral --color-bg-subtle fill, not pepper: the dot and the Open status already use pepper, and a third pepper signal in one row would compete. aria-current="page" when the row's link is the page you are on (the customer thread pages), aria-current="true" when the thread is open in the pane beside a list page (caterer enquiries at 62rem+).
  • Loading: .inbox-skeleton-rows, each aria-hidden, with a hidden "Loading your enquiries" status.
  • Empty, no results, error, offline replace or top the list: "No enquiries yet", "No open enquiries", "We couldn't load your enquiries. Your messages are safe.", and an offline banner over the cached list.

Responsive behaviour

  • Below 62rem: the inbox shows the list or one thread, never both (.inbox-layout); opening a row navigates to its thread, and the thread's back link returns to the list.
  • LG and up (62rem+): the list sits in a 20–26rem column beside the open thread; the current row is marked.
  • All widths: name and summary truncate to one line with an ellipsis so rows keep an even rhythm; the full text is in the thread heading and is still read in full by screen readers. Time and status never truncate or wrap.
  • At 320px a long name such as "Auntie Euphemia's Kittitian & Nevisian Sunday Kitchen…" truncates; the status stays on the second line.
  • Long inboxes paginate: "Showing 1–20 of 25" with pagination under the list.

Theming

The row reads --color-border-default (rules), --color-bg-surface-sunken (hover), --color-bg-subtle (current), --color-fg-default, --color-fg-muted and --color-fg-subtle (name, summary, time) and --color-accent (unread dot). Status labels bring their own tokens. In dark, hover is stone-900 and current stone-800 on the stone-950 page, so the open row still stands out; the dot becomes the lighter pepper-300.

Accessibility

Role and pattern

A list of links: <ul aria-label>, each <li> holding one <a class="inbox-row">. The link's accessible name is its whole text, read in order: "Unread. Pelau House, 9:42 a.m., Sat 21 Nov · 120 guests, Replied". Nothing inside the row is separately interactive. The filter above (All, Open, Replied, Declined, Closed) is a segmented control with aria-current.

Keyboard

KeyAction
Tab / Shift+TabMoves from row to row.
EnterOpens the thread (navigates, or loads it into the pane at 62rem+ and moves focus to its heading).

Focus

The shared ring draws around the whole row. Returning from a thread on phones puts focus back on the row you opened, so long inboxes don't make people start over.

Labelling

The picture has empty alt (the name follows); the avatar is aria-hidden. "Unread." is visually hidden text inside the name, not an aria-label, so the rest of the row is still read. The inbox count in the header says "1 unread enquiry".

Motion

Hover fill over --duration-fast; nothing else. Skeleton shimmer stops under reduced motion.

Touch

Each row is a full-width target about 81px tall, well over 44px, with no inner targets to miss.

Content

  • Name: the caterer's business name for customers; the customer's full name for caterers ("Priya Ramdial"), or "Former Sweet Hand user" after deletion. Never an email address.
  • Time of last activity, in Toronto time: today as a time ("9:42 a.m."), yesterday as "Yesterday", the last 6 days as the weekday ("Thu"), older as "Tue 6 Oct", other years with the year.
  • Summary: event date, guests, then (caterer view) occasion: "Thu 5 Nov · 60 guests · Corporate events". The event date gets the year when it isn't 2026: "Sat 12 Jun 2027".
  • Status: one word from the fixed set Open, Replied, Declined, Closed.
  • No message preview: messages are private, and the row stays scannable.
