Breadcrumb

Most Sweet Hand screens sit one step below a page people already know, so they show a single eyebrow back link. The full breadcrumb trail is held in reserve for screens three or more levels deep.

Overview

Two components answer the question "where am I, and how do I get back?". Pick by depth, not by taste.

  • Eyebrow back link (.eyebrow): a chevron and the parent page's name, sitting just above the h1. Every mock that needs a way back uses it: "Caterers" on the caterer page, "Occasions" on the Weddings listing, "Overview" on dashboard pages below 62rem, "Review queue" and "Caterers" in the operator console. It is one link, so it reads as one thought.
  • Breadcrumb (.breadcrumb): an ordered trail with a slash between levels and the current page last. No mock uses it today. Use it only when a screen is three or more levels below a top-level page and people need to jump to a middle level, for example an operator going from Caterers / Pelau House / Name change back to Pelau House.
Choosing between eyebrow and breadcrumb
SituationUseExample
Top-level page reached from the site header (Caterers, Occasions, Inbox)NeitherThe header link already carries aria-current="page".
One level below a known pageEyebrow"‹ Caterers" above Pelau House.
Dashboard or operator page at 62rem and widerNeither (eyebrow hidden with .until-lg)The side navigation shows the current section.
Three or more levels deep, middle levels usefulBreadcrumbCaterers / Pelau House / Name change.

Neither replaces the primary navigation: use the site header for top-level places, tabs to switch views of one object and pagination to move through a list. The browser Back button still works everywhere because listing state lives in the URL (L2-003).

Anatomy

  1. Back chevron16px outline chevron (.icon--sm), aria-hidden="true". It is what says "back"; the label does not repeat it.
  2. Eyebrow labelThe parent page's name in --text-body-sm, muted; the whole row is a 44px target.
  3. Crumb linkEach ancestor, muted, underlined on hover.
  4. SeparatorA "/" drawn by li + li::before in --color-fg-subtle, so screen readers never read it.
  5. Current pagePlain text with aria-current="page", ink and medium weight. Not a link.

Sizes

Both use --text-body-sm at every breakpoint. They are wayfinding, not headings, so they never compete with the h1 below them.

States

Links are never disabled and have no pressed look. Hover and focus are forced here with data-state; the current crumb uses the real aria-current.

  • Current is ink at medium weight, not pepper. Pepper red means "selected / you are here" in lists people choose from (filters, side nav); a pepper crumb would compete with the side nav's current item on the same screen.
  • Loading: the eyebrow renders with the page shell, before data, because its target is known from the route. On pages/caterer/loading it stays live while the gallery and title are skeletons.

Responsive behaviour

  • XS to MD (below 62rem): dashboard, inbox and enquiry pages show the eyebrow (.eyebrow.until-lg) because the side nav or the inbox list is not on screen. The thread view uses it to get back to the list (.inbox-layout--thread).
  • LG and XL (62rem and wider): those eyebrows hide; the side nav or the list beside the thread shows where you are. The caterer page, the Weddings listing and operator detail pages keep the eyebrow at every width, because no persistent navigation shows their parent.
  • Breadcrumb: crumb links are 44px tall below 48rem and 24px from 48rem. The trail wraps onto a second line rather than scrolling (flex-wrap). With .breadcrumb--collapse, below 48rem only the parent crumb stays, prefixed "‹", so a phone shows the same one-step affordance as an eyebrow.
  • Long caterer names ("Auntie Euphemia's Kittitian & Nevisian Sunday Kitchen and Celebration Catering" on pages/caterer/edge) wrap inside the crumb; they are never truncated, because the truncated part may be the only difference between two caterers.

Theming

No component tokens: both read three text roles and the shared focus ring. Links are --color-fg-muted, hover and current are --color-fg-default, the separator is --color-fg-subtle. In dark the stone ramp flips (muted becomes a light stone on near-black) and every pair keeps at least 4.5:1. To re-skin, override the text roles on a wrapper; never colour a crumb with the accent.

Accessibility

Role and pattern

Breadcrumb: <nav aria-label="Breadcrumb"> around an <ol>, the last item marked aria-current="page" (APG Breadcrumb). Eyebrow: a single <a href> placed before the h1 in source order; it gets no landmark of its own because one link is not a navigation region.

Keyboard

KeyAction
Tab / Shift+TabMoves through the crumbs (or the eyebrow) in reading order; it comes after the skip link target, so "Skip to main content" lands just above it.
EnterFollows the link. The current crumb is not focusable.

Focus

The shared ring (2px --color-focus-ring, 3px offset) wraps the full 44px eyebrow row, chevron included, so the target and the ring match.

Labelling

The link text is the destination: "Caterers", "Overview", "Review queue". The chevron is hidden from assistive technology. Two links with the same text and the same destination (the header's "Inbox" and an eyebrow "Inbox") are fine under WCAG 2.4.4.

Motion

None. Colour and underline change instantly on hover, so there is nothing for reduced motion to remove.

Touch

The eyebrow is 44px tall (--target-comfortable) at every width. Crumb links are 44px tall below 48rem (L2-065.1), where a collapsed breadcrumb leaves one link that must be easy to tap; from 48rem, with pointer input, they drop to 24px (--target-min), which still meets WCAG 2.5.8.

Content

  • Use the parent's name exactly as the navigation shows it. The dashboard side nav calls the first page "Overview", so the eyebrow says "Overview", not "Dashboard".
  • No "Back to" prefix: the chevron already says back. Write "Inbox", not "Back to inbox"; "Enquiries", not "Back to enquiries".
  • Crumbs use page titles in sentence case: "Review queue", "Name change". Caterer names are written as the caterer writes them ("Pimento & Thyme", "Black Cake Co.").
  • Never put the site name or "Home" first; the wordmark in the header already goes home.
