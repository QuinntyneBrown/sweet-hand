Checklist

Round checks that say what is done and what is left: the ten steps a new caterer completes before submitting their profile, and the short lists of rules and consequences inside operator and account dialogs.

Overview

A check is a 28px circle: an empty ring for "to do", a filled success disc with a tick for "done", a danger ring for "needs attention". It always sits beside words that say the same thing, so the circle is never the only signal.

  • Setup checklist: the caterer dashboard while a profile is a draft (dashboard/draft). A meter ("8 of 10 done") above a .section-list whose rows link to each step, each led by a check. This is the list a caterer works through; each row is a link.
  • Compact checklist (.checklist): a plain list of checked lines inside a dialog: the submission rules an operator confirms in dialogs/approve-profile, or "All 10 sections are complete" in dialogs/submit-profile. Items can be marked missing (data-missing) or highlighted as the reason a submission failed (data-highlight).

Don't use a check for a choice the user makes: that is a checkbox. Don't use it for a status of something else (an enquiry, a review): that is a status label. A list of what an action will do ("Kendra gets an email with your reason") is a list with icons, not a checklist of done items. Setup progress as a single number is a meter.

Anatomy

  1. Done check.check--done: --color-success-solid disc, tick in --color-bg-surface, 16px icon.
  2. To-do check.check: 2px --color-border-strong ring, empty. With data-missing the line turns muted.
  3. Needs-attention check.check--error: 2px --color-danger-solid ring with an exclamation in --color-danger-fg.
  4. LabelThe step in plain words, with a visually hidden state prefix ("Done: ", "To do: ", "Needs attention: ").
  5. Highlightdata-highlight: the line turns --color-danger-fg at medium weight after a failed submit.

Responsive behaviour

  • Checks never shrink (flex: none); labels wrap beside them, aligned to the centre of the first line in compact lists.
  • Setup rows are at least 4.5rem tall at every width, so each whole row is a large target on phones. Below 62rem the dashboard is one column; the checklist follows the intro and meter.
  • In dialogs the compact list uses the dialog's width (full screen below 48rem, a centred panel above).

Theming

Checks read status tokens: --color-success-solid (done disc), --color-bg-surface (tick), --color-border-strong (to-do ring), --color-danger-solid and --color-danger-fg (needs attention). Missing lines read --color-fg-muted. Done is green on purpose: it is the one place the success colour appears in a list, and it never means "selected", which stays pepper red elsewhere. In dark the disc is a lighter green and the tick a near-black surface, keeping both pairs above their minimums.

Accessibility

Role and pattern

A plain list. The check is decorative (aria-hidden="true"); state is spoken through a visually hidden prefix. Setup rows are links, one per step, labelled by their title and meta. No ARIA widget pattern applies; the meter follows the APG Meter guidance with aria-valuetext="8 of 10 done".

Keyboard

KeyAction
TabSetup checklist: each row link in order. Compact checklist: not focusable.
EnterOpens that step's page (Photos, Menu, Food safety…).

Focus

The shared ring wraps the whole setup row. Returning from a step page lands focus on the page heading; the meter and checks have already updated.

Labelling

"Done: Email verified", "To do: Photos, Add at least 3 photos · 2 so far", "Needs attention: Food handler certificate, Expired 30 Sep 2026". A list where every item is done may omit the prefix when the heading or sentence says so ("All 10 sections are complete").

Motion

Checks change state without animation; the meter bar eases over --duration-deliberate, which reduced motion zeroes.

Touch

Setup rows are full-width links at least 72px tall. Compact items are not targets.

Content

  • Name the step as a noun on the dashboard ("Photos", "Menu", "Food handler certificate") and put the progress in the meta: "Add at least 3 photos · 2 so far", "5 dishes", "Oshawa and 4 more".
  • In dialogs, write each item as a finished fact: "Email verified", "Certificate valid until 22 Jan 2030", "Recorded in the audit log under your name".
  • Needs-attention meta says what happened and when: "Expired 30 Sep 2026", "Replace photos 2 and 5".
  • The meter counts steps, not percent: "8 of 10 done", labelled "Ready to submit".

Drift fixed during extraction:

  • .check--error contained the full circled danger icon, drawing a ring inside a ring; it now holds just the exclamation strokes.
  • Needs-attention meta was coloured with inline style="color: var(--color-danger-fg)"; a [data-highlight] rule for setup rows is proposed instead.
  • data-missing and data-highlight existed in CSS but no mock used them, although submit-profile/invalid promises the items are "highlighted on your checklist too". The highlighted state is now specified here.
  • dialogs/download-data used done checks for the contents of an export and dialogs/suspend-caterer used .checklist for a list of consequences with plain icons; neither is a checklist.
