Text field

A single line of text: a business name, an email, a guest count, an event date. White, square-ish, with a stone edge that turns pepper on focus and sorrel when something is wrong.

WCAG 2.2 AAStatus: stableNative <input>.input

Overview

Use a text field for one short value people type. It always sits in a form field, which gives it a label, help and a message.

  • Use the input type and autocomplete that match the data, so phones show the right keyboard and browsers can fill it: email for sign-in, tel for a caterer's phone, date for the event date, password with a Show toggle.
  • Guest counts, the smallest and largest event, and 6-digit codes are type="text" with inputmode="numeric", not type="number". That avoids spinners and wheel-scrolling that change the value, and lets the field keep "fifty" so the error can say what to fix.
  • Search inputs (type="search") come in two shapes: the compact .search with a leading icon, and the pill .search-field used on operator lists and for areas. When a search suggests values as you type, it is a combobox.
  • Input group (.input-group + .addon) joins a fixed prefix or suffix to the field, such as "+1" before a Canadian phone number or "guests" after a count.
  • Read-only value (.read-only-value) replaces the input with plain text when there is nothing to edit, as on a profile under review.

For more than one line, use a textarea. For a fixed list of answers, use a select or a radio group.

Anatomy

  1. ContainerFull width, 44px minimum (--control-height-md), --radius-md (12px), 1px edge in --field-border (--color-border-strong), fill --field-bg.
  2. Value--text-body (16px, so phones don't zoom on focus) in --field-fg; padding --space-2 --space-3.
  3. Placeholder (optional)A format hint in --color-fg-subtle. It is never the label and never the only instruction.

Sizes

Medium is the default everywhere. Large is for the single-column auth screens (sign in, register, forgot and reset password, two-factor code), where the field is the whole task. Small is for dense desktop toolbars only: from 48rem it is 36px; below 48rem it grows to 44px (L2-065.1).

Heights --control-height-sm/md/lg; text --font-size-sm / md / lg. Small text is 14px, so iOS zooms on focus; keep small fields off phone-facing forms.

States

Hover and focus are forced with data-state; invalid, disabled and read-only use aria-invalid, disabled and readonly.

Both themes

  • Hover darkens the edge to --color-fg-muted. Focus draws the 2px pepper ring flush with the edge (offset 0) and turns the edge pepper too.
  • Invalid doubles the edge in sorrel (1px border + 1px inset shadow), so it differs from default by width as well as hue. It always comes with a .field__error message.
  • Read-only uses the sunken fill and keeps the strong edge; the value stays selectable and in the tab order. While a form submits, inputs go read-only, not disabled.
  • Disabled fades to the subtle fill and disabled text, and leaves the tab order. Use it only when a field can't apply, and say why in the help.

Responsive behaviour

  • Every input is width: 100% of its field; the form caps the line at 40rem. Short pairs (Event date + Guests) share a .field-row from 36rem.
  • Text is 16px at medium and large, so iOS Safari never zooms the page on focus. Small (14px) is for 48rem and up; below 48rem it already grows to 44px tall, and it should not be used on phone-facing forms.
  • Date inputs use the platform picker: a wheel on iOS, a calendar on Android and desktop. min and max (2 days to 2 years ahead) limit it; the server checks again.
  • Input groups never wrap: the addon stays joined to the field. Keep addons to a few characters ("+1", "guests") so the field keeps room at 320px.
  • In the operator toolbar, search and date fields are at least 10rem and wrap to new rows.

Theming

The input declares three component tokens that alias semantic ones, and every state overrides them instead of setting colours directly:

.input { --field-bg: var(--color-bg-surface); --field-border: var(--color-border-strong); --field-fg: var(--color-fg-default); }
/* hover → --field-border: --color-fg-muted;  focus → --color-focus-ring;  invalid → --color-danger-solid
   disabled → --field-bg: --color-bg-subtle, --field-fg: --color-fg-disabled;  read-only → --field-bg: --color-bg-surface-sunken */

The same tokens drive select and textarea, so a re-skin is one rule: .reply-box .textarea { --field-bg: var(--color-bg-surface-sunken); }. In dark, the field is stone-950 on a stone-950 page and the stone-500 edge carries it at 3:1 or more. Invalid becomes sorrel-300 and the ring pepper-300.

Accessibility

Role and pattern

Native <input> with a <label for> (see form field). Errors set aria-invalid="true" and are referenced from aria-describedby. The password Show toggle is a toggle button (aria-pressed, aria-controls) that switches type between password and text and keeps its label. Search inputs sit in a role="search" form. autocomplete tokens meet WCAG 1.3.5: name, email, organization, tel, postal-code, current-password, new-password, one-time-code.

Keyboard

KeyAction
Tab / Shift+TabMoves into and out of the field. Read-only fields are tab stops; disabled ones are not.

Esc in a searchClears the value (browser behaviour); in a dialog, a second Esc closes the dialog.
PasteAlways allowed, including passwords and one-time codes (WCAG 3.3.8).

Focus

The ring sits flush on the edge (offset 0) and the edge turns pepper, which gives a 2px+ indicator at 3:1 against the page. Focus never moves on its own while typing. After a failed submit it goes to the error summary, whose links return it here.

Labelling

Every input has a visible label, or a visually hidden one when the context is unmistakable (the search on a list headed "Caterers"). The accessible name matches the visible words. Placeholders are format hints only ("Name or ID"); they vanish on typing and have low contrast by design.

Disabled fields are exempt. The search icon is decorative; the label names the field.

Motion

Edge colour and the invalid shadow transition over --duration-fast; reduced motion zeroes it. There are no shake animations on error.

Touch

Medium (44px) and large (52px) meet the phone target, and the label adds to the tap area. Small grows to 44px below 48rem. The password Show button is a 44px-tall link button on phones.

Content

  • Placeholders show a format, never the label: "Name or ID", "Business or owner name", "FH-2024-000000". Leave them out when the help already shows an example.
  • Accept what people naturally type: postal codes with or without a space and in any case ("m1b2k3" becomes "M1B 2K3"), phone numbers with spaces, dashes or brackets, guest counts with a comma ("1,200").
  • Name the unit in the label or an addon, not in the value: "Largest event" + "guests".
  • The Show toggle says "Show" and stays "Show"; aria-pressed carries the state.
  • Prices and other free text stay free text where caterers word them themselves: "From $18 per person".
