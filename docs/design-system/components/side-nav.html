Side navigation

In the caterer dashboard and the operator console, a quiet text list down the left names every section and marks the one you are in with pepper red. On phones and tablets the dashboard swaps it for a stacked section list with done marks.

Overview

Side navigation lists the sections of a work area. It is the same visual language as the listing's cuisine filter: a vertical column of large muted text, the current item in pepper red and semibold. There are no boxes, icons or highlight bars, matching the reference design's filter column.

  • Caterer dashboard (nav aria-label="Dashboard"): Overview, Business details, Cuisines and areas, Guests and occasions, Photos, Menu, Food safety; then Enquiries (with "2 unread"), Reviews, Account.
  • Operator console (nav aria-label="Operator"): Review queue (7), Recent changes, Caterers, Reviews, Metrics; then Audit log, Cuisines, Operators, Breach register.
  • From 62rem only. Below that the dashboard overview shows a section list (.section-list): one large row per section with a status mark, opening one section at a time (L2-045.2). Operators use the site menu sheet.

Use the site header for the 2 to 3 top-level destinations, tabs or the segmented control to switch views inside one section (Inbox "All · Open · Replied"), and the filter list for filtering results. Don't put actions ("Add a dish") in the side nav.

Anatomy

  1. Item.filter-list__item link: --text-body-lg (18px), --color-fg-muted, 44px tall, no padding or background.
  2. Current itemaria-current="page": --color-fg-accent (pepper), semibold.
  3. GroupEach <ul class="filter-list"> is a group; groups are separated by --space-8 (the .side-nav gap), with no headings.
  4. Count (optional).filter-list__count in caption type: "2 unread", "7".

The anatomy is drawn with a .stack--lg wrapper because .side-nav itself is hidden below 62rem and would vanish on a phone reading this page.

Legacy: .nav-link, .sidebar, .sidebar__group, .side-nav__title

The base kit has a boxed app sidebar (.sidebar with a surface background and a right border, uppercase .sidebar__group headings, .nav-link rows whose current state is ink, not pepper) and a .side-nav__title heading. No mock uses any of them; the mocks chose the filter-list look for every work area. They remain in components.css for parity only. Don't use them.

Sizes

Side navigation has one size: the --layout-sidebar-width column (15rem) with 44px items in 18px text. Section-list rows are 72px tall (4.5rem) so the title, the summary and the status fit with room to tap.

States

Hover and focus are forced with data-state; current uses aria-current="page". Section rows add a status through .check modifiers.

Responsive behaviour

  • Below 62rem .side-nav is hidden (display: none). The dashboard overview shows the .section-list (.until-lg); each section page shows an .eyebrow back link to the overview. Every dashboard destination is also in the caterer's site menu sheet; operators reach theirs only through the operator site menu.
  • From 62rem the side nav appears as the first column of .work-layout (15rem, --space-12 gap) and sticks --space-8 from the top while the main column scrolls (L2-045.3).
  • From 75rem the dashboard adds the live preview pane on the right (.work-layout--preview); the nav does not change.
  • Section rows are full width with no side padding beyond --space-1; long summaries wrap rather than truncate.

Theming

Items read --color-fg-muted, --color-fg-default on hover and --color-fg-accent when current; counts --color-fg-subtle. Section rows read --color-border-default hairlines between rows and --color-bg-surface-sunken on hover; the checks read --color-border-strong (to do), --color-success-solid with a --color-bg-surface tick (done) and --color-danger-solid with --color-danger-fg (needs attention). In dark the pepper current item lifts to --palette-pepper-300 and the done check to light callaloo with a near-black tick. No component tokens.

Accessibility

Role and pattern

A <nav> landmark with a unique aria-label ("Dashboard", "Operator") holding lists of links; the current page has aria-current="page". This is plain navigation, not the APG menu or tree pattern: no arrow-key handling, no role="menu". The section list is a <ul> of links inside a section headed "Your profile".

Keyboard

KeyAction
Tab / Shift+TabMoves through the links in order, group by group.
EnterOpens the section.

The side nav comes after the header and before the main column in the DOM, inside <main>; the skip link therefore lands just before it. Screen-reader users can jump past it by landmark.

Focus

The shared ring wraps each item. Because the nav is sticky, it never overlaps the focused element in the main column (they sit in separate grid columns).

Labelling

  • Item text is the section name exactly as the page title says it: "Cuisines and areas" opens a page titled "Cuisines and areas".
  • Counts are words, not just numbers, where it matters: "2 unread". The queue count "7" is read as "Review queue 7"; make it "Review queue, 7 waiting" with a visually hidden word if testing shows confusion.
  • Section rows hide the check from assistive tech and put the status in words at the start of the title: "Done: ", "To do: ", "Needs attention: ".

Current is not colour alone: it is also semibold and announced as "current page".

Motion

Colour changes over --duration-fast; nothing moves. Reduced motion needs no change beyond the zeroed duration.

Touch

Side nav items are 44px tall with no gap, stacked; each row is the full column width so a thumb cannot miss. Section rows are 72px.

Content

  • Section names are nouns in sentence case, two or three words at most: "Business details", "Guests and occasions", "Food safety", "Breach register".
  • Order by frequency within each group, and put the business-running group (Enquiries, Reviews, Account) after the profile group.
  • Section summaries say what is there or what is missing, with numbers: "2 cuisines · 5 areas", "Add at least 3 photos · 2 so far", "Certificate valid until 14 Mar 2029", "Replace photos 2 and 5".
  • The back link on a section page always says "Overview", the name of the page it returns to.
