Error page

When a whole page can’t be shown — it doesn’t exist, it’s closed to this account, the server failed, Sweet Hand is down for maintenance — the system page says so plainly under the normal header, with three round food photos and one way forward.

WCAG 2.2 AAStatus: stable.system-page

Overview

A system page replaces the whole <main> when the requested page cannot be served. The site header and footer stay, so people are still clearly on Sweet Hand and can navigate away. The content is a centred column: a .photo-row of three round food photos (the brand's signature, used here so an error still feels like Sweet Hand), a display-size heading, one or two sentences, the recovery actions and a small code line.

Six pages, each served with the matching HTTP status:

PageHTTPHeadingWhen
Not found404Page not foundNo such page, and a record exists but this visitor may not see it (a draft, a removed caterer, someone else's enquiry). The body is identical either way so nothing leaks (L2-034.1, L2-014.2).
No access403No accessA customer or caterer session reaches an operator-only area. Logged as a security event (L2-056.3).
Server error500Something went wrongAny unhandled failure. Shows the request's correlation ID to quote (L2-089.4); never internal details.
Rate limited429Slow down a littleToo many requests from one network; sent with Retry-After (L2-082.1).
Offline(service worker)You’re offlineA page that is not in the cache is opened with no connection.
Maintenance503Back soonThe planned window (between 1:00 and 5:00 a.m. Toronto time), announced beforehand by the site banner (L2-088).

Choose something else when only part of the page failed. A list that didn’t load is an empty state in error tone inside the page; a role-restricted section inside an app area the person can otherwise use (the audit log for a non-Admin operator) is a forbidden empty state, not a 403 page. Ongoing problems that still let people use the site are a banner.

Anatomy

  1. Site headerThe normal header for the visitor's role (public, customer, caterer "for caterers", operator "Operator"), so navigation still works.
  2. Photo rowThree round food photos, the middle one larger, aria-hidden; --space-6 below. Different photos per page.
  3. HeadingThe page's <h1> at --text-display: two or three plain words.
  4. Explanation.prose body-large: what happened, whose fault, what to do.
  5. Actions.system-page__actions: one large primary, an optional large secondary, centred and wrapping.
  6. Code line.system-page__code: "Error 404", a reference with Copy, or the maintenance window, in --color-fg-subtle.

Variants

All six pages, as they render at phone width (live mocks, light and dark alternating).

Server error with reference

The 500 page is the only one with two recovery paths and a copyable reference: the correlation ID of the failed request, which support can search for.

Sizes

System pages have one layout: a 34rem centred column with the display heading and large buttons. It adapts to the viewport (see Responsive) but has no size variants.

States

The page is static; its actions carry the states. The rate-limited and server-error pages have the interesting ones: a disabled-then-enabled retry and a busy retry. Forced with the real attributes where they exist.

  • Rate limited: the retry starts disabled (aria-disabled="true", so it stays focusable and can explain itself) with the wait in its label, "Try again in 1 minute". It does not count down every second. When Retry-After passes, the label becomes "Try again", the button enables and a polite status says "You can try again now".
  • Offline: the page retries by itself when the connection returns and reloads the requested URL.
  • Maintenance: Check again reloads; when the window ends early the page reloads by itself.
  • Copied: Copy becomes a "Copied" status for 2 seconds, announced politely.

Responsive behaviour

  • All sizes: the column is max-width: 34rem, centred, with the container's --layout-margin on each side. Top padding is --space-16, bottom --space-8, so the photos sit well below the header on every device.
  • Below 36rem (xs): the display heading is 48px (--font-size-5xl steps up to 64px only from 62rem), the photo row is 272px wide and fits 320px, and two large buttons stack when they cannot share a line; the primary stays first.
  • From 48rem (md): the header shows its full navigation again; the system page itself does not change.
  • The 500 reference is a 36-character UUID; it wraps at its hyphens rather than causing sideways scroll at 320px; Copy follows on the next line when it does not fit.

Theming

System pages read the page tokens: --color-bg-canvas, --color-fg-default for the heading, --color-fg-default at --text-body-lg for the explanation, --color-fg-subtle for the code line and --color-bg-photo behind photos that are still loading. There are no component tokens. Buttons follow the button theming: in dark the ink primary becomes light stone.

Photos are photographs and never get tinted or filtered by a theme. Choose a different trio per page so each error looks distinct in screenshots and support tickets.

Accessibility

Role and pattern

An ordinary document: <header>, <main id="main"> with one <h1>, <footer>, and a skip link. No widget role. The <title> starts with the problem: "Page not found — Sweet Hand", "Something went wrong — Sweet Hand" (WCAG 2.4.2). The HTTP status is real, so assistive tech, browsers and search engines all get the same answer.

Keyboard

KeyAction
TabSkip link, header links, then the primary action, the secondary action, Copy, then the footer.
Enter / SpaceActivates the focused action.

Focus

On a full page load focus starts at the top as usual. When the app shows a system page after a client-side navigation, focus moves to the <h1> (with tabindex="-1") so screen readers start at the explanation.

Labelling

The photo row is aria-hidden with alt="" photos: they are decoration here. Copy names what it copies (aria-label="Copy reference"). The reference is in <code>. Buttons with icons keep their text ("Try again").

Contrast

Motion

None beyond the buttons' own transitions; photos do not zoom. The busy Try again spinner keeps turning under reduced motion because it is status.

Touch

Primary and secondary are large (52px). Copy is a small link button (36px) set apart from the large buttons by the code line spacing.

Content

  • Heading: two or three plain words about the situation, not the code: "Page not found", "No access", "Something went wrong", "Slow down a little", "You’re offline", "Back soon".
  • Explanation: what happened, whose fault, what to do: "That one’s on us, not you. Try again in a moment." / "Your account can’t open this page. If you think it should, ask a Sweet Hand admin."
  • Reassure about data where people might worry: "Your enquiries and messages are safe."; "enquiries can be sent once you’re back online".
  • Never confirm a hidden record exists: the 404 says "the caterer may no longer be listed", which is true of a removed caterer and a page that never existed alike.
  • Never show internals: no stack traces, server names or exception text; only the correlation ID.
  • Times are Toronto time and say so: "until 3:00 a.m. Toronto time".
  • The code line is secondary: "Error 404", not "404 Not Found" as a heading.
