Switch

A switch turns one setting on or off the moment it is flipped, with no Save button. Sweet Hand barely needs one: no mock uses it today, so it waits in the kit for the first instant setting.

Overview

The switch is a native <input type="checkbox" role="switch"> inside a <label class="switch">. It looks like a pill track with a sliding thumb; on is pepper red.

Where the mocks use it: nowhere. Every on/off choice in the mocks sits inside a form that autosaves or submits (dietary tags, "Use as cover photo", consent), so each one is a checkbox. The account page has no preferences, emails are out of scope (mocks README, open question 14), and there is no theme setting in the product (the theme toggle belongs to the mock bar). .switch is kept, tokenised and documented so the first real instant setting has a ready answer, not a new invention.

  • Use a switch only when the change applies immediately and can be undone by flipping it back, and the result is visible or confirmed straight away.
  • Use a checkbox for anything inside a form, anything that needs Save or Submit, any agreement, and any list of options.
  • Use a button (usually opening a confirmation dialog) when turning something off has consequences, such as hiding a caterer page or suspending a caterer. Those are actions, not settings.
  • Use a segmented control for a choice between two named views.

The labels on this page ("Pause new enquiries", "Show the live preview") are illustrations. Neither has an L2 requirement; adding one needs a requirement, a design and a mock first.

Anatomy

  1. Track44 × 24px pill (--target-comfortable × --target-min, --radius-full): --color-border-strong off, --color-accent on.
  2. Thumb20px circle (--icon-size-md) in --color-bg-surface with --shadow-1; slides 20px to the right when on.
  3. LabelNames the setting, in .switch__text. It does not change with the state.
  4. Description (optional)<small> in --color-fg-muted: what "on" means for customers.

Variants

Label right (default)

Track first, then the label: the control lines up with the left edge of the form like a checkbox does.
HTML
<label class="switch">
  <input type="checkbox" role="switch" name="pause" aria-describedby="pause-status">
  <span class="switch__text">Pause new enquiries<small>Your page says you’re not taking bookings</small></span>
</label>
<p class="visually-hidden" role="status" id="pause-status"></p>

Label left, in a settings row

In a list of settings the label leads and the track sits at the end of the row, so the eye reads the setting first. Put the text before the input inside the same label and spread them with .cluster--between.

The whole row is the label, so tapping the text toggles too.
HTML
<label class="switch cluster cluster--between" style="display: flex;">
  <span class="switch__text">Pause new enquiries<small>…</small></span>
  <input type="checkbox" role="switch" name="pause" checked>
</label>

Sizes

The switch has one size: a 44 × 24px track inside a row at least 44px tall. A smaller switch would fall below the phone target in L2-065; a larger one would outweigh the label.

States

Off and on use the real checked attribute; hover and focus are forced with data-state (on + hover uses data-state="checked" data-hover); disabled uses disabled.

Both themes

  • Saving: the switch moves at once (optimistic). If the server refuses, it moves back and an error toast says why ("We couldn’t pause enquiries. Try again."). Do not show a spinner inside the track.
  • Disabled is 50% opacity. Only disable when the reason is on screen next to it; otherwise leave it enabled and explain on change.
  • There is no invalid state: a switch cannot hold a wrong value. There is no mixed state either; use checkboxes for a parent of several settings.

Responsive behaviour

  • The switch is the same at every breakpoint. The row is at least 44px tall (min-height: var(--target-comfortable)), so it meets L2-065 on phones without a phone rule.
  • In a label-left settings row the text wraps and the track stays pinned to the end; at 320px the description may take three lines, which is fine.
  • Never put two switches on one line.

Theming

The switch reads semantic tokens directly: track --color-border-strong (off), --color-fg-muted (off, hover), --color-accent (on) and --color-accent-hover (on, hover); thumb --color-bg-surface with --shadow-1.

In dark the thumb becomes the near-black surface and the on track lifts to --palette-pepper-300, so on reads as a bright track with a dark thumb. Pepper on the track is correct brand use: on is "selected". Re-skin by overriding --color-accent on a wrapper.

Accessibility

Role and pattern

role="switch" on a native checkbox (APG Switch). Screen readers announce "Pause new enquiries, switch, off". The checked state maps to on/off natively, so no aria-checked is needed.

Keyboard

KeyAction
Tab / Shift+TabMoves to and from the switch.
SpaceToggles and applies the setting.
EnterNo effect (native checkbox behaviour); never wire Enter to submit a surrounding form.

Focus

The shared 2px pepper ring follows the pill shape with a 3px offset, so it stays visible against the pepper "on" track.

Labelling

  • The label names the setting ("Pause new enquiries"), never the action ("Turn on") and never the state ("Paused"). The role already says on or off.
  • Announce the result of a change that is not visible in place through a polite live region ("New enquiries paused").

The thumb against each track also needs 3:1 (WCAG 1.4.11); those two pairs are not yet in contrast-pairs.json and are listed in the extraction report.

Motion

The thumb slides and the track colour fades over --duration-base (200ms) with --ease-standard. Reduced motion zeroes the duration; the state still changes.

Touch

The 44px row is the target, track and label together. Leave 8px between rows of switches.

Content

  • Name the setting as a short positive phrase in sentence case: "Pause new enquiries", "Show the live preview". Avoid negatives ("Don’t show…"): off-on-a-negative is a double negative.
  • The description says what customers or the caterer will see when it is on.
  • Never add "On"/"Off" text beside the track; the track and the role carry it.
  • If turning something off loses data or hides a business from customers, it is a button and a confirmation, not a switch.

Sources

No mock uses the switch. It comes from the base kit in docs/mocks/assets/ui.css. The places where a switch might have been expected all use checkboxes, correctly:

  • dialogs/photo-details/default ("Use as cover photo", saved with the dialog)
  • pages/account/default (no preferences: details, devices, data, delete)
  • dialogs/account-menu/default (no theme or notification settings)

Drift fixed during extraction: the kit sized the switch with literals (2.75rem × 1.5rem track, 1.25rem thumb, 0.125rem inset) and gave the row only a 24px minimum height; the system uses --target-comfortable, --target-min, --icon-size-md and --space-0-5, raises the row to 44px, and adds hover colours for off and on.
