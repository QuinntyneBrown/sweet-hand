Accordion

An accordion tucks optional detail behind a short label so the screen stays calm. Sweet Hand builds it on native details and summary, so it opens with no script and is found by find-in-page.

WCAG 2.2 AAStatus: stable, lightly usedNative <details>.accordion

Overview

Use an accordion when people need some of the content some of the time and showing all of it would bury the screen: an operator's raw numbers behind a chart, or the longer answers on an information page. Each row is a <details> element; its <summary> is the button.

  • Grouped accordion (.accordion): several related rows in one group, each opening on its own.
  • Single-open group: the same markup with a shared name attribute on each <details>, so opening one closes the others. Use it when the rows are alternatives.
  • Quiet disclosure: one bare <details> inside a component, styled by that component. The operator metrics page uses it under every bar chart: "Show as a table" reveals the same weekly numbers as an accessible table.

Do not use an accordion for:

  • Navigation between screens. The caterer dashboard on phones lists its sections as links that open a screen (side navigation), not panels that expand in place.
  • Editing. Sweet Hand never puts a form inside a panel that opens on the page; button-triggered editing opens a dialog or a new screen.
  • Content everyone needs, such as a caterer's menu, areas or allergens. Hiding allergens behind a toggle would break the "food safety is first-class" rule; show them as tags on the dish.
  • Switching between views of the same thing; use tabs or a segmented control.

Anatomy

  1. Group.accordion: 1px --color-border-default outline, --radius-md, --color-bg-surface.
  2. Summary (the button)Native <summary>, --text-label at --font-size-md, padding --space-4, at least 44px tall.
  3. IndicatorA "+" in --color-fg-subtle that turns 45° into "×" when open. Decorative: the expanded state comes from <details>.
  4. Panel.accordion__body: muted body text, padding 0 --space-4 --space-4, so it lines up with the summary label.
  5. Row separator1px --color-border-default between rows (details + details), never a gap or a shadow.

Sizes

The accordion has one size: the summary is at least 44px (--target-comfortable) with --space-4 padding, and the quiet disclosure keeps the same 44px target in smaller muted text. Density comes from the content, not from a size modifier.

States

Open and closed come from the native open attribute; hover and focus are forced here with data-state on the summary. There is no disabled state: if a row has nothing to show, leave it out (the metrics page drops "Show as a table" from a chart that failed to load).

  • Expanded: the indicator rotates to "×"; the panel appears below the summary and pushes content down. Nothing overlays.
  • Hover: the summary row takes --color-bg-subtle. The quiet disclosure has no hover fill; its text stays muted.
  • Focus: the shared 2px pepper ring around the summary on :focus-visible.
  • Loading and error belong to the content, not the accordion: a chart that fails shows an alert in place of the chart and no disclosure.

Responsive behaviour

  • All breakpoints: the group fills its column; the summary label wraps onto more lines and the indicator stays centred on the right. Nothing truncates.
  • XS and SM (below 48rem): the accordion runs edge to edge inside the page margin (--layout-margin, 16px). Panel text keeps the 16px inset so it never touches the border.
  • MD and up (48rem+): panel prose is capped at the reading measure (--layout-measure, 62ch) by the base p rule even when the group is wider.
  • Quiet disclosure tables scroll sideways inside .table-wrap rather than widening the page; the metrics tables have two columns and fit at 320px.

Theming

The accordion reads semantic tokens directly and has no component tokens: --color-bg-surface (group), --color-border-default (outline and separators), --color-bg-subtle (summary hover), --color-fg-default (label), --color-fg-muted (panel text) and --color-fg-subtle (indicator). The quiet disclosure inherits from .chart-card summary: --color-fg-muted in --text-body-sm.

In dark, the surface and the canvas are the same stone-950, so the 1px stone-750 outline is what holds the group together; hover lifts the row to stone-800. To re-skin, override the semantic tokens on a theme scope; do not add a background tint or a shadow to the group, which would break Sweet Hand's flat surfaces.

Accessibility

Role and pattern

Native <details>/<summary>, which browsers expose as a disclosure button with an expanded or collapsed state (APG Disclosure; a group of them is the APG Accordion without the optional arrow keys). No ARIA is added. Put plain text in the summary, not a heading element: a heading inside the button role is flattened by some screen readers. Name the whole group with the section heading above it.

Keyboard

KeyAction
Tab / Shift+TabMoves between summaries, then into the open panel's links and buttons.
Enter, SpaceOpens or closes the focused row.
Arrow keysNot used. Rows are reached with Tab like any button, which is what the native element gives everywhere.

Focus

Focus stays on the summary when it toggles; it never jumps into the panel. Browser find-in-page searches closed panels and opens the matching row automatically, so content is not lost by being folded.

Labelling

The summary text is the accessible name and must make sense on its own when read in a list of buttons: "Show as a table" sits inside a chart section labelled "Enquiries", so it is announced in that context. Don't put the state in the label ("Hide table"); the expanded state is announced for you.

Motion

Only the indicator moves: a 45° turn over --duration-base (200ms) and the hover fill over --duration-fast. The panel opens instantly; there is no height animation to wait for. Reduced motion sets both durations to near zero.

Touch

The whole summary row is the target, at least 44px tall and full width. The quiet disclosure also keeps a 44px row even though its text is small.

Content

  • Summaries are short noun phrases or questions in sentence case, Canadian English: "Who sees it", "How long we keep it", "Show as a table". Four or five words at most.
  • Front-load the distinctive word so a scanning eye finds it: "For caterers", not "Information for caterers".
  • Panels answer in one or two short paragraphs. If a panel needs headings of its own, it deserves its own page.
  • Never hide prices, allergens, licensing statements or anything a person must agree to inside a closed row.
  • Keep the label the same when open or closed.

Sources

The grouped accordion is part of the original kit (docs/mocks/assets/ui.css) and is not used on any current screen; its copy here comes from the information pages. The quiet disclosure is extracted from:

  • pages/admin-metrics/default ("Show as a table" under six charts)
  • pages/admin-metrics/invalid (same disclosures with a corrected date range)
  • pages/admin-metrics/partial (failed charts drop the disclosure)
  • pages/privacy/default, pages/terms/default and pages/about/default (example copy)

Drift fixed during extraction: the "Show as a table" summaries are display: flex, which removes the native disclosure triangle, so nothing showed they expand; the system gives them the accordion's "+" indicator (CSS change requested). The kit's summary had no hover transition; it now fades over --duration-fast.
