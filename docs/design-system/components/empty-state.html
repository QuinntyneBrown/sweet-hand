Empty state

An empty state fills the space where content would be — no dishes yet, no caterers match, the list didn’t load — with one line of why and one way forward.

Overview

An empty state replaces a list, grid or panel that has nothing to show. It keeps the page around it (header, title, filters, side navigation) and centres four parts in the content area: a round image, a title, one sentence and usually one action. It covers five situations:

  • First run: nothing has been created yet. "What do you cook best?" on an empty menu, "Show people your food" on an empty photo manager, "No enquiries yet" in a new customer's inbox.
  • No results: filters or a search exclude everything. "No caterers match these filters", "No closed enquiries".
  • Error: the content failed to load. "We couldn’t load caterers", with Try again and a reference.
  • Offline: the content needs a connection and nothing is cached.
  • Forbidden: the person is signed in but their role cannot see this section. "Only Admins can see the audit log".

Choose something else when:

  • The whole page cannot be served (404, 500, maintenance): an error page.
  • Content is still loading: a skeleton. Never show "No caterers" while the request is in flight.
  • Part of a page failed while the rest is fine (one chart on the metrics page): an inline alert in that part.
  • The empty thing is a whole setup flow (a caterer's first dashboard): the welcome text, setup meter and checklist do the job; the empty state appears inside each section (menu, photos) instead.

Anatomy

  1. Image.empty__icon: a 72px stone circle with a 28px outline icon, or a .photo-row of three round food photos. Always aria-hidden.
  2. Title.empty__title: a real heading at the level that fits the page outline (--text-h3 look whatever the level).
  3. Text.empty__text: one or two sentences, muted, at most 36 characters per line so it stays a tidy block.
  4. Actions.empty__actions: one primary (only if the screen has no other) and optionally one secondary, centred and wrapping.

Variants

Sizes

Two sizes. Full (default) fills a page's content area; compact sits inside a tab panel, a filtered list, a card or a dialog.

  • Retrying: Try again goes busy; when the request succeeds the empty state is replaced by skeletons and then content; when it fails again, the same error returns with a new reference.
  • Recovering from offline: when the connection returns, the region reloads by itself; the person does not have to press Try again.
  • First run ends the moment the first item exists: after "Add your first dish" saves, the menu list replaces the empty state and focus moves to the new dish's row.

Responsive behaviour

  • All sizes: centred column; text block capped at 36ch; actions wrap and stay centred. The icon circle stays 72px.
  • Below 36rem (xs): the photo row (72 / 104 / 72px with 12px gaps, 272px in all) still fits a 320px screen with the 16px margins. When two actions do not fit side by side they stack, primary first.
  • From 48rem: on the listing, the empty state sits in the results column beside the filter list; the filters stay usable. On the dashboard it sits in .work-main beside the preview pane.
  • From 62rem: the inbox empty state occupies the list column; the thread column stays empty rather than repeating the message.
  • Full-size padding (--space-12 top and bottom) is the same everywhere; use compact on phones only where the empty state sits inside a smaller container, not to save space on a whole page.

Theming

The empty state reads --color-bg-subtle and --color-fg-default for the icon circle, --color-fg-default for the title and --color-fg-muted for the text. .empty--error swaps the circle to --color-danger-bg with a --color-danger-icon glyph. In dark the circle becomes a dark-stone disc and the photos keep their colours (they are photographs; never filter them).

Accessibility

Role and pattern

Plain content: a heading, a paragraph and links or buttons. No widget role. Error empty states that replace content after a failed request are role="alert" so the failure is announced; a no-results state that appears after the filters change is announced through the result count's polite live region ("0 caterers"), not by making the empty state itself live. See the APG Alert pattern for the error case.

Keyboard

KeyAction
Tab / Shift+TabReaches the actions in order: primary, then secondary.
Enter (links), Enter / Space (buttons)Activates.

Focus

Focus is not moved to an empty state that appears on page load. After the person removes the last item (the last dish), focus moves to the empty state's primary action so they are not left on a deleted row. After a filter change empties the list, focus stays on the filter they used.

Labelling

The title is a real heading (h2 in a page section, h1 when the empty state is the whole page, a <p> inside a dialog whose own title already names it). The icon circle and photo row are aria-hidden; their photos have alt="". A reference number is in <code> so it is read character by character with most screen readers' settings.

Motion

None. Empty states appear without animation; photos do not zoom (the caterer-card hover zoom does not apply to the decorative photo row).

Touch

Actions are 44px (medium) or 52px (large first-run buttons) and wrap with 12px between them.

  • Never "No data", "Nothing here" or "0 results". Say which things.
  • Name the caterer's or customer's world, not the database: "enquiries", "dishes", "caterers".
  • References are lower-case, hyphenated and in <code>: "Reference 7f3c-91ad".
  • Keep the warmth of a first run and the calm of an error; no exclamation marks, no jokes about failure.
