Combobox

The area and postal code search: type “scar” or “M1B 2K3” and Sweet Hand suggests the GTA area it means. It is the one way to say where an event is.

Overview

The combobox answers "Where’s your event?" (L2-011, L2-012). People type an area name ("Scarborough", "Mississauga") or a Canadian postal code. Matching areas appear as suggestions; a valid GTA postal code resolves to its area, and only its first three characters ("M1B") are used and stored.

  • Search dialog: the header's search icon (and the phone browse bar's "Area or postal code" button) opens dialogs/search. The field autofocuses; suggestions float in a raised .suggestions panel below it; "Or choose a whole region" offers the five regions as a fallback.
  • Listing aside: from 62rem the filter column on /caterers has the same field under "Area", above the region list. Its suggestions sit in flow (.suggestions--inline) so they push the region list down instead of covering it.

When not to use it: for a plain search that doesn't suggest values (operator "Business or owner name"), use the pill search text field. For a short fixed list, use a select. To filter by several areas at once, use the region checkboxes in the filter list. There is no free-text search by caterer or dish name (mocks README, open question 8).

Anatomy

  1. Field.search-field .input: a 52px pill (--control-height-lg, --radius-full) with the --field-* tokens; role="combobox".
  2. Pin icon20px area pin in --color-fg-subtle, decorative. The pin means "area" everywhere in Sweet Hand.
  3. Listbox panel.suggestions: --color-bg-surface-raised, 1px --color-border-default, --radius-lg, --shadow-3, 8px below the field. The inline variant drops the border, shadow and padding.
  4. Option.suggestion, 44px, --radius-md. The active option gets --color-bg-subtle and a 2px pepper bar at its start edge.
  5. Match<mark> around the typed part, shown bold rather than highlighted, so the colour stays calm.
  6. Hint.suggestion__hint: the region ("City of Toronto", "Peel"), caption size, --color-fg-subtle.

In context

Sizes

One size: the 52px pill (--control-height-lg) with 44px options, in the dialog and the aside alike. Area search is a primary task wherever it appears, so it gets the hero size. The width follows the container: the dialog body (up to 32rem) or the 15rem filter column. The panel is always exactly as wide as the field.

                                  • Empty: placeholder and help only; aria-expanded="false". In the dialog the field has focus on open and the regions sit below.
                                  • Typing with suggestions: after the first character, up to 8 areas whose names start with the text (case- and accent-insensitive), alphabetical. No option is active until an arrow key is pressed; the matched part is bold.
                                  • No match ("Barrie"): the listbox closes and a .suggestions__empty status says "No matching areas". It is not an option, so arrow keys don't land on it. The regions stay available.
                                  • Invalid postal code ("12345"): shown on submit, not while typing. aria-invalid, a .field__error "Enter a valid postal code, like M5V 2T6", and the value is kept.
                                  • Out of area ("K1A 0B1", a real code outside the GTA): a .field__warning in a polite status, "Sweet Hand currently serves Toronto and the GTA", not an error. The region list stays as the way forward.
                                  • Busy ("M1B 2K3" submitted): the field goes readonly, Show caterers shows aria-busy, Cancel is disabled. Results arrive in under a second, then the dialog closes on the filtered listing.
                                  • Disabled: only when the listing itself can't load (offline, empty states), together with the region buttons.

                                  Responsive behaviour

                                  • Below 36rem the search dialog is a bottom sheet (--radius-xl top corners), full width. The field autofocuses, so the keyboard opens with the sheet; floating suggestions stay above it because the panel follows the field in the dialog body.
                                  • From 36rem the dialog is centred (32rem wide). The mock note said "from 640px"; the CSS and this system use the 36rem breakpoint.
                                  • Below 62rem the listing has no filter column. The browse bar's "Area or postal code" button (.btn--ghost with the pin) opens the dialog. From 62rem the aside field is the combobox, with inline suggestions.
                                  • Phones get a capitals keyboard (autocapitalize="characters") with a Search key (enterkeyhint="search"), and autocomplete="postal-code" offers the person's saved postal code.
                                  • With more than 8 matches the panel scrolls inside itself; the page never scrolls sideways at 320px.

                                  Theming

                                  The field uses the text field's --field-bg, --field-border and --field-fg with the pill radius. The panel reads --color-bg-surface-raised, --color-border-default and --shadow-3; options read --color-fg-default and --color-bg-subtle; the active bar --color-accent; hints --color-fg-subtle; the empty status --color-fg-muted. Pepper appears only as the bar on the active option ("you are here" in the list).

                                  In dark the raised panel is stone-850 over a stone-850 dialog, so its border and deeper shadow carry the edge; the bar is pepper-300. The <mark> never gets a background in either theme.

                                  Accessibility

                                  Role and pattern

                                  APG Combobox, list autocomplete with manual selection. The <input> has role="combobox", aria-autocomplete="list", aria-controls pointing at the role="listbox", aria-expanded true only while options show, and aria-activedescendant naming the active role="option" (which has aria-selected="true"). DOM focus stays in the input throughout. The dialog's <form role="search"> and the aside's search form are landmarks.

                                  Keyboard

                                  KeyAction
                                  TypingFilters suggestions; opens the listbox when there are matches.
                                  ↓ / ↑Opens the listbox if closed; moves the active option, wrapping at the ends. The input text doesn't change until Enter.
                                  Alt+↓Opens the listbox without moving the active option.
                                  EnterWith an active option: fills the field with it and closes the list. With none: submits what was typed (a postal code, or an exact area name).
                                  EscCloses the listbox; a second Esc clears the field; in the dialog, a third closes the dialog and returns focus to the search icon.
                                  ← / →, Home / EndMove the text cursor in the input (not the options).
                                  TabCloses the listbox without choosing and moves on (to the regions, then Cancel and Show caterers).

                                  Focus

                                  Real focus stays in the field, with the flush pepper ring. The active option is shown by the fill and the 2px pepper bar, and is scrolled into view. Picking an option keeps focus in the field. Submitting closes the dialog and moves focus to the result count on the listing.

                                  Labelling

                                  The field is named "Area or postal code" with a visually hidden label. The dialog title "Where’s your event?" and the visible help give the question and an example. The listbox is "Matching areas"; each option's name is the area, and its region hint is part of the option text ("Scarborough, City of Toronto"). A polite status announces the count as it changes ("3 areas match", "No matching areas"). Errors and warnings are referenced from aria-describedby.

                                  Error in a dialog

                                  The active option is identified by its fill and bar together with aria-selected. The pepper bar against the fill and the field edge against the dialog surface still need their own entries in contrast-pairs.json (see the report).

                                  Motion

                                  Suggestions appear and update without animation, so fast typists never wait. The field edge transitions over --duration-fast. The dialog's sheet or scale entry follows dialog, and reduced motion zeroes it.

                                  Touch

                                  The field is 52px and options are 44px, full width, with no gaps between them. A tap on an option picks it; a tap outside closes the list without picking.

                                  Content

                                  • Question as the dialog title: "Where’s your event?". Placeholder: "Area or postal code". Help: "An area like Scarborough, or a postal code like M1B 2K3."
                                  • Suggestions are L2-010 area names exactly ("Whitchurch-Stouffville", "Downtown Toronto") with their region as the hint. Neighbourhood names that aren't areas (Leslieville, Malton) don't appear (open question 4).
                                  • Postal codes are shown uppercase with a space ("M1B 2K3") whatever was typed. Only the first three characters are kept; say so where it matters ("We keep only the first 3 characters").
                                  • Error: "Enter a valid postal code, like M5V 2T6". Out of area: "Sweet Hand currently serves Toronto and the GTA". No match: "No matching areas". No exclamation marks, no blame.
