Button group

Two ways to pick one option from a short row: the segmented button group, and the quiet text filter above every inbox and operator list.

WCAG 2.2 AAStatus: stable.btn-group.segmented

Overview

Both variants show every option at once, and exactly one is on. They differ in weight.

  • Segmented text filter (.segmented) is the one the product uses everywhere: a wrapping row of words with counts above a list. Marcia's inbox has "All 4 · Open 1 · Replied 1 · Declined 1 · Closed 1"; Kendra's enquiries and every operator list have one too. It is quiet like the filter list in the reference design: muted words, the current one in pepper and semibold. Items are links with aria-current="page" when the filter is in the URL, or buttons with aria-pressed when it filters in place.
  • Button group (.btn-group) joins outlined buttons into one pill; the pressed segment is pepper on a pepper tint. Use it for 2 to 4 short, mutually exclusive view options in a toolbar, such as the operator metrics "Show by: Day · Week · Month", which a native select handles today. No mock uses it yet; this is the approved shape.

When not to use them: to choose one value inside a form, use a radio group. To filter by several values at once (cuisines, areas), use the filter list or checkboxes. To switch between panels on one page, use tabs. With more than about seven options, or options that may grow (operators, cuisines), use a select.

Anatomy

  1. Group.btn-group with role="group" and an aria-label naming the choice ("Show by"). Outer ends keep the pill radius; inner edges are square and overlap by 1px.
  2. SegmentA secondary .btn with aria-pressed="false"; 44px tall, label in sentence case.
  3. Pressed segmentaria-pressed="true": --color-accent-subtle fill, --color-fg-accent label, --color-accent border, raised one layer so its border shows on both sides.
  4. Current filterA .segmented item with aria-current="page" (or aria-pressed="true"): pepper and semibold, so it does not rely on colour alone.
  5. Item and countMuted body text, 44px tall, --space-5 between items. The count is a .filter-list__count caption after the word.

When the filter is part of the URL (/inbox?status=open), each item is a link and the current one carries aria-current="page". Back and Forward work, and a filtered view can be shared or bookmarked.

Segmented text filter: toggle buttons

When the list filters in place without changing the URL, items are buttons with aria-pressed, and the result count below updates in a role="status" region. A filter with no matches stays enabled; disable it only when it can never match.

Button group

Three segments at 44px; two compact segments, 36px from 48rem (44px on phones), for a dense operator toolbar.
HTML
<div class="btn-group" role="group" aria-label="Show by">
  <button class="btn" type="button" aria-pressed="false">Day</button>
  <button class="btn" type="button" aria-pressed="true">Week</button>
  <button class="btn" type="button" aria-pressed="false">Month</button>
</div>

Loading

While counts load, the row is skeleton bars, aria-hidden; the page's loading status speaks for it.

Sizes

The segmented filter has one size: body text in 44px rows. The button group takes its segments' size: medium (44px) by default, small (36px, .btn--sm on every segment) only in a desktop operator toolbar. Below 48rem small segments grow back to 44px (L2-065.1), so a compact group is never compact on a phone. Never mix sizes within a group.

Small · 36px from 48rem (--control-height-sm; 44px below) and medium · 44px (--control-height-md).

  • Selected is always exactly one. Pressing the selected segment again does nothing; it does not unselect.
  • Active: the segmented filter has no pressed look of its own, so the hover colour shows until the list updates. Group segments nudge down 1px like every .btn.
  • Loading: after a choice, the list below shows its skeleton or keeps the old rows with aria-busy="true". The filter itself stays interactive.
  • Disabled only for an option that cannot apply at all. A status with 0 items stays enabled and leads to the list's empty state ("No open enquiries").

Responsive behaviour

  • Segmented wraps (flex-wrap, no row gap, --space-5 between items) and never scrolls sideways. At 320px Marcia's five statuses take two lines; Leah's seven caterer states take three. Don't truncate a label or hide statuses behind "More".
  • From 62rem (LG) the inbox list and the open thread sit side by side, and the segmented filter wraps inside the list column, not the page.
  • Button group does not wrap: segments stay joined. Keep it to 4 segments of one or two words (about 280px at medium). If a group cannot fit at 320px, use a select below 36rem.
  • Neither variant changes size by breakpoint; the 44px rows already suit touch.

Theming

The pressed segment reads --color-accent-subtle (fill), --color-fg-accent (label) and --color-accent (border) on top of the button's own tokens. The segmented filter reads --color-fg-muted at rest, --color-fg-default on hover, --color-fg-accent when selected and --color-fg-disabled when disabled. Pepper here means "selected", which is the only job the accent has.

In dark, the tint becomes pepper-950 with a pepper-300 label and border, and muted text becomes stone-350. To re-skin, override the button tokens on the group (.btn-group { --btn-bg: …; }) or color on .segmented. Never swap the selected colour for ink: an ink segment would read as a primary action.

Accessibility

Role and pattern

The button group is a set of toggle buttons (APG Button, toggle) in role="group" with an aria-label. The segmented filter is a list of links (<ul aria-label="Filter by status"> with aria-current="page") or of toggle buttons. Both are deliberately not tabs: they filter one list, they don't swap panels.

Keyboard

KeyAction
Tab / Shift+TabMoves through each segment or item in order. Every option is a tab stop, so the selection is never hidden behind arrow keys.
EnterFollows a filter link, or presses a toggle button.
SpacePresses a toggle button (group segment or segmented button).

Focus

The shared pepper ring with a 3px offset. On a link filter focus lands on the new page's <h1>, or stays on the filter if the update is in place. A pressed segment is raised one layer (--z-raised) so the ring and pepper border are not clipped by the neighbouring segment.

Labelling

The group's aria-label names the choice ("Show by", "Filter by status"). Each item's text is its name, count included: "Open 1". Where a count alone is unclear, add hidden context: Open 1<span class="visually-hidden"> enquiry</span>. The result count below ("4 enquiries · 1 unread") is the live region; the filter does not announce itself.

The selected state never relies on hue alone. The segmented filter adds semibold weight; the group adds a fill and border change and, as corrected below, semibold weight.

Motion

Colour transitions over --duration-fast; group segments nudge 1px when pressed. Reduced motion zeroes both.

Touch

Every segmented item is at least 44px tall and as wide as its words, with 20px between items. Group segments are 44px; small segments are 36px only from 48rem and grow to 44px below it. There is no gap between segments, but targets don't overlap.

Content

  • Labels are the status nouns used everywhere else, in lifecycle order, "All" first: All · Open · Replied · Declined · Closed; All · Draft · Pending review · Changes requested · Published · Suspended · Removed.
  • Counts follow the word after a space, as figures with thousands separators ("Published 1,204"). Show 0 rather than hiding the option.
  • One or two words per segment in a button group: "Day", "Week", "30 days". Sentence case, no icons.
  • A filter only filters. "Held reviews 1" in the queue's kind filter leaves the queue for another page, which is a near-miss: prefer a plain link below the list.
