Textarea

Room to write: a caterer's description, an enquiry message, a reply to a thread, the reason an operator gives. It shares the text field's look and adds a counter when there is a limit.

Overview

Use a textarea when the answer is a sentence or more. Size it to the answer you expect, so people can see what they've written.

  • Form textarea (.textarea in a form field): the business description (9 rows, 50–2,000 characters), the enquiry message (5 rows), a dish description (3 rows, up to 300), a note when declining an enquiry (3 rows, up to 500), an operator's reason for suspending a caterer.
  • Reply box (.reply-box): the bar pinned to the bottom of a thread, with a 2-row pill-cornered textarea and a primary Send button beside it. It is the only place a textarea sits next to its submit button.

When a limit applies, show a .field__counter and let people go over: they may paste a long draft and trim it. When the answer is one line (a name, a postal code), use a text field. Never use a textarea for structured data such as allergens or dietary tags; those are checkboxes.

Anatomy

  1. BoxThe text field's container: --field-* tokens, --radius-md, --text-body. Height from rows, never less than 2.5 × 44px (110px).
  2. Resize handleVertical only (resize: vertical), so the box never breaks the layout sideways.
  3. Counter (optional).field__counter under the box, end-aligned beside the help; sorrel with data-over.

Sizes

One width (the column) and a height set by rows to fit the expected answer. The CSS minimum is 2.5 × --control-height-md (110px); the reply box lowers it to --control-height-lg (52px) because it grows as you type.

  • Over limit: no maxlength. The counter turns sorrel at limit + 1, the textarea becomes invalid on submit, and the error says by how much: "Keep your reply under 2,000 characters. It’s 2,143 now."
  • Sending (reply box): the textarea goes readonly and Send shows aria-busy. On success the box empties and the message joins the thread; on failure the text stays, with an error above.
  • Offline: the reply box stays readable but Send is blocked with an explanation (mocks README, open question 17); the draft isn't lost.
  • Disabled is rare: a closed enquiry hides the reply box and explains why, rather than showing a dead one.

Responsive behaviour

  • Full width of the form column, capped by .form at 40rem; in dialogs, the dialog's width. Dialogs with long text (enquiry) fill the screen below 48rem, so the textarea has room above the keyboard.
  • The reply box is position: sticky; bottom: 0 with env(safe-area-inset-bottom) padding, so it clears the iPhone home indicator. From 62rem the thread sits beside the inbox list and the box spans the thread column only.
  • The reply textarea grows with its content to about a third of the viewport height, then scrolls, so the thread above stays visible on a phone.
  • Text is 16px at every width, so focusing never zooms the page on iOS.

Theming

The textarea uses the text field's component tokens (--field-bg, --field-border, --field-fg) and the same state overrides. The reply box adds its own surface (--color-bg-canvas, a top --color-border-default rule) and rounds the textarea to --radius-lg. In dark, the box sits on the stone-950 canvas with a stone-750 rule. Re-skin by overriding the field tokens on .reply-box, not by restyling .textarea.

Accessibility

Role and pattern

Native <textarea> with a <label for>; aria-describedby lists message, help and counter. The reply box is a <form> with a visible label ("Your reply") and a submit button named "Send reply".

Keyboard

KeyAction
Tab / Shift+TabMoves into and out of the textarea. Tab never inserts a tab character.
EnterNew line. It never sends, in the reply box included, so a reply can't go out half-written.
Ctrl/⌘+Enter (reply box)Sends the reply, the same as the Send button.

Focus

The flush pepper ring and pepper edge, as on the text field; in the reply box it follows the larger radius. After sending, focus stays in the emptied textarea so a follow-up can be typed at once.

Labelling

Visible labels name the reader where it matters: "Note to Priya", "Reason (sent to Kendra)", "Your response". The counter is referenced from aria-describedby. It isn't announced on every keystroke; a polite status announces "143 characters too many" after typing pauses past the limit.

Motion

Edge colour transitions over --duration-fast. The reply box's growth is instant, not animated. Reduced motion zeroes the transition.

Touch

Every textarea is at least 52px tall (reply box) or 110px (forms). The Send button beside the reply is 44px and sits 8px from the textarea, so a thumb can't hit both. The resize handle is optional on touch, because growing replaces it.

Content

  • Say who will read it, in the label or help: "Shown to Priya in the email and the enquiry", "The caterer never sees who reported them", "Public on your page as “Response from Pelau House”".
  • Prompt with what's useful, not "Enter text": "What you’d like to eat, serving style, timing".
  • State the range in help ("50–2,000 characters") and the count as "225 / 2,000".
  • No placeholder text in textareas; it reads as content already written.
  • Links typed into replies show as plain text, and the help says so.

Drift fixed during extraction: limits were enforced three ways: a visible counter with no maxlength (decline note), a counter plus maxlength (enquiry, review response, thread, where 2,143 characters sat in a 2,000 maxlength box), and maxlength with no counter (suspend reason). The rule is a counter, no maxlength, and validation on submit. The report dialog's counter was not referenced by aria-describedby. The thread's over-limit counter used an inline colour instead of data-over.
