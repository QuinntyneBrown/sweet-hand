Photo tile

One round food photo in the caterer's photo manager, with its caption, a Cover tag on the first, buttons to move it and a link to edit it. Tiles also show uploads in progress, photos still processing, and the read-only view an operator reviews.

Overview

Photos lead a caterer's listing: the first one becomes the round photo on their card. The photo manager (pages/profile-photos) is a grid of tiles, 3 to 30 photos, in the order they appear on the public page. Each tile is a round photo with the caterer's caption under it; order changes with move buttons, and everything else (caption, cover, replace, remove) happens in dialogs/photo-details. There are no inline forms and no drag-only interactions.

  • Editable tile: photo, optional Cover tag, caption, move up / down, "Edit".
  • Uploading tile: the new photo under a scrim with its percentage, a progress bar and "Cancel".
  • Processing tile: a placeholder circle with a clock while the server prepares the image.
  • Read-only tile: photo and caption only, while a profile is in review or when an operator reviews it.
  • Upload tile (.upload-tile): a dashed circle that adds photos from inside the grid; the toolbar's "Add photos" button is the default entry point.

Public pages show photos with the gallery, listing cards with the caterer card. A single file field (the food handler certificate) is a file upload row, not a tile.

Anatomy

  1. PhotoRound .photo, at most 10rem, --color-bg-photo behind it while loading.
  2. Cover tag.photo-tile__cover on photo 1 only: ink pill, --text-caption semibold, 12px above the bottom of the circle.
  3. Caption.photo-tile__caption: the caterer's own description (5–125 characters), small and muted, clamped to two lines. It is the photo's alt text on the public page.
  4. Move.photo-tile__move: two 44px icon buttons, "Move photo 1 up / down".
  5. EditLink-style small button, "Edit photo 1", opens the photo details dialog. Additional actions go in .photo-tile__actions.

Upload tile

A <label> for a visually hidden file input, 10rem round, dashed 2px --color-border-strong. It also accepts dropped files.

Sizes

Photo tiles have one size: the photo fills its column up to 10rem. The grid changes column count by breakpoint (see Responsive), never the tile.

Responsive behaviour

  • Below 48rem: two columns, 16px apart horizontally and 32px vertically. At 360px each photo is about 150px across.
  • 48rem to 75rem: three columns. 75rem and up: four columns, and the dashboard's listing-card preview appears beside the grid.
  • The photo never exceeds 10rem, so wide columns add space around it rather than enlarging it.
  • Captions clamp at two lines; the full caption is in the edit dialog. Below 48rem the small "Edit" button grows to 44px (L2-065.1).
  • Reordering is always by buttons, so it works the same with touch, mouse, keyboard and switch access. Dragging tiles is not supported.

Theming

No component tokens. Photos sit on --color-bg-photo until they load. The Cover tag reuses the action pair (--color-action / --color-fg-on-action); upload progress uses --color-bg-scrim with --color-fg-on-scrim, a fixed dark scrim in both themes so white text stays readable over any photo. The progress bar is ink (--color-action) on a --color-bg-subtle-hover track: progress is not a selection, so it is never pepper. Missing captions read --color-warning-fg; the upload tile reads --color-border-strong, turning --color-accent with --color-accent-subtle while files are dragged over it.

Accessibility

Role and pattern

A list (<ul aria-label="Photos, in the order they appear on your page">) of tiles. Reordering uses buttons, which WCAG 2.5.7 (Dragging Movements) requires anyway. The upload tile is a <label> for a native file input. Progress is a role="progressbar" named after the file. Edit opens a modal dialog (APG Dialog).

Keyboard

KeyAction
TabMove up → move down → Edit, tile by tile, in photo order.
Enter, SpaceMoves the photo one place; focus follows the photo and stays on the same button. On Edit, opens the dialog.
Enter, Space on the upload tileOpens the system file picker.

Focus

The shared ring. A photo moved to the first or last place keeps focus on its now-unavailable button (aria-disabled, not disabled). The upload tile shows the ring when its hidden input has focus. When an upload finishes, focus does not jump.

Labelling

  • In the manager the visible caption is the description, so the image has alt=""; on the public page the same caption becomes the alt text.
  • Buttons name the photo: "Move photo 2 up", "Edit photo 2", "Cancel upload of IMG_2076.heic". After a move a polite live region says "Photo 2 moved to position 1. It is now your cover."
  • The percentage over the photo is aria-hidden; the progress bar carries the value. Upload start and finish are announced by the save status and a toast ("Photo added").

Motion

Progress bars ease their width over --duration-deliberate; reduced motion zeroes it. Photos have a slow 3% scale settle that reduced motion removes. Moves are instant.

Touch

Move buttons are 44px circles with 8px between them and 8px above Edit; Edit is 44px tall below 48rem. The upload tile is 10rem across.

Content

  • Captions are the caterer's words, describing the food as they name it: "Curry chicken scattered with shado beni over white rice", "Rum-soaked black cake dusted with icing sugar". 5–125 characters.
  • The Cover tag is always "Cover". The subtitle explains it: "6 of 30 · the first photo is your cover".
  • Errors name the file and the rule: "IMG_2041.jpg: Photos must be under 15 MB and at least 800 pixels on the shorter side".
  • Help under "Add photos": "JPEG, PNG, WebP or HEIC · under 15 MB · at least 800 pixels on the shorter side".

Drift fixed during extraction:

  • Every manager tile repeated the caption as the image's alt text right beside the visible caption; in the manager the image is now alt="".
  • First/last move buttons used disabled; now aria-disabled="true" so focus survives a move to the end.

  • The operator grid used <span class="photo-tile__caption">, the manager <p>; both are <p>.
