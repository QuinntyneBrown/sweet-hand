Select

A native dropdown for one answer from a known list: the event area grouped by region, the occasion, an operator filter. The phone's own picker does the hard work.

Overview

Use a select when there is exactly one answer from a list of about 5 to 50 known values, and seeing them all at once doesn't help. Sweet Hand always uses the native <select>: phones show their own wheel or sheet, screen readers know it, and it never needs a custom listbox.

  • Form select with a placeholder option: "Event area" in the enquiry (<option value="">Choose an area</option>, then the 30 areas in five <optgroup>s: City of Toronto, Peel, York Region, Durham, Halton), "Occasion" (8 occasions), "Primary area" in a caterer's settings.
  • Filter select: a real first option meaning "everything" instead of a placeholder: "All operators", "All actions" in the audit log; "Show by: Week" on metrics.

When not to use it: with 2 to 4 options, show them as a radio group or button group. When several can apply (occasions a caterer serves, dietary tags), use checkboxes. When the list is long and people know what they want to type (an area or a postal code), use the combobox. A select never navigates or submits on change.

Anatomy

  1. BoxThe text field's container: --field-* tokens, 44px, --radius-md, native appearance removed (appearance: none).
  2. Selected value or placeholder option--text-body. The placeholder option ("Choose an area") has value="", so required catches it.
  3. ChevronTwo gradient triangles in currentColor, 5px, 12–18px from the end; --space-10 end padding keeps text clear of it.

Variants

Form select with placeholder and groups

Areas grouped by region in the same order as the filter list; occasions in the order the mocks use.

    <optgroup label="Peel">…</optgroup>

Filter select

The first option is a real value ("All operators"); changes apply when Apply is pressed, never on change.

Sizes

One size: 44px (--control-height-md) with 16px text, in forms and toolbars alike. A select never sits on the large auth screens, and it has no small size: a compact select would shrink the native picker's trigger below the phone target. Width follows the field (full width in forms, at least 10rem in a toolbar).

Medium · 44px; end padding --space-10 for the chevron.

States

Hover and focus are forced with data-state; invalid and disabled use aria-invalid and disabled. A select has no read-only state in HTML: show a read-only value instead.

Both themes

Choose your primary area
Choose your primary area
  • Open is drawn by the operating system (a wheel on iOS, a sheet on Android, a list on desktop). Sweet Hand doesn't style it, and the color-scheme token makes it follow light or dark.
  • Invalid: the placeholder is still selected on submit, or the value no longer applies. The message says what to choose.
  • Busy: while a form submits, a select is disabled, because it can't be read-only. Text fields in the same form go read-only. Restore it if sending fails.
  • Warning: a valid choice the caterer doesn't usually cover ("This caterer doesn’t list Oshawa as an area they serve") keeps the default edge and adds a .field__warning.

Responsive behaviour

  • Full width in forms; two selects share a .field-row from 36rem (Event area beside Postal code).
  • On phones the native picker opens over the keyboard area, with optgroup labels as section headers. This is the main reason Sweet Hand never replaces <select> with a custom dropdown.
  • The closed box shows the chosen option on one line; a long option ("Religious and cultural celebrations") is clipped by the browser at 320px, never wrapped. Keep options short and front-load the meaning.
  • In the operator toolbar each select is at least 10rem and wraps to a new line with the other filters.

Theming

The select shares the text field's component tokens (--field-bg, --field-border, --field-fg) and state overrides. The chevron is drawn in currentColor, so it follows --field-fg: ink in light, stone-100 in dark, faded when disabled. Native option lists follow color-scheme (set by the theme). Re-skin with the field tokens, never by replacing the chevron with an image.

Accessibility

Role and pattern

Native <select> (combobox role with a listbox popup, handled by the browser) with a <label for>. Groups use <optgroup label>, which screen readers announce. A custom listbox would need the full APG Listbox pattern; Sweet Hand doesn't build one.

Keyboard

KeyAction
Tab / Shift+TabMoves into and out of the select.
Space, Enter, Alt+↓Opens the list (platform-dependent).
↑ / ↓Changes the option; on some platforms this changes the value without opening, which is why nothing may happen on change.
LettersType-ahead: "S" jumps to Scarborough, "Sc" stays there, "Sp" doesn't exist so it stays.
EscCloses the list without changing the value.

Focus

The flush pepper ring and pepper edge, like the text field. Choosing an option keeps focus on the select, and nothing else moves (WCAG 3.2.2).

Labelling

A visible label names the question ("Event area"); the placeholder option is an instruction ("Choose an area"), not a label. Errors and warnings are referenced from aria-describedby. In the busy state, don't remove the label or the value.

Motion

Edge colour transitions over --duration-fast; the native list opens with the platform's own motion, which honours the OS reduced-motion setting.

Touch

44px tall at every width, plus the label as an extra target. The native picker gives full-size touch rows on phones.

Content

  • Placeholder options start with "Choose": "Choose an area", "Choose an occasion", "Choose your primary area".
  • Filter selects start with a real "All …" option: "All operators", "All actions".
  • Option names match the rest of the product exactly: GTA municipalities as in L2-010 ("Whitchurch-Stouffville"), occasions as on caterer pages ("Funerals and repasts").
  • Order by meaning, not alphabet, when there is one (Day, Week, Month); otherwise alphabetical within each group.
  • The error repeats the instruction: "Choose your primary area", not a different idea.
