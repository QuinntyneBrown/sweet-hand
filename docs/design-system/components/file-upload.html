File upload

Caterers upload two kinds of file: photos of their food and a copy of their food handler certificate. The native file input does the work; a button-styled label, a file row and an optional drop tile make it look like Sweet Hand.

Overview

The control is always a real <input type="file" class="file-input visually-hidden">. It is hidden visually but stays in the tab order, and the visible part is the <label for> right after it, styled as a button. Clicking, tapping or pressing Space on the focused input opens the device picker: on a phone that offers the camera and the photo library (L2-045.1).

  • Photos (pages/profile-photos): "Add photos" is the screen's one primary button. Several files at once (multiple), JPEG, PNG, WebP or HEIC, under 15 MB, at least 800 pixels on the shorter side (L2-041). Each file becomes a photo tile that shows its own progress.
  • Certificate (pages/profile-certificate): one optional file, PDF, JPEG or PNG up to 10 MB, shown as a .file-row with Replace and Remove once uploaded. Only the caterer and operators ever see it.
  • Drop tile (.upload-tile): a round dashed target that also accepts dragged files. It is in the kit but in no mock yet; when used it is an extra way in, beside the button, never the only one.

Don't use a file upload to collect a business licence, ID or anything the platform would appear to certify. Food handler details are the caterer's own statement (AGENTS.md); the certificate copy is optional.

Anatomy

  1. File icon24-unit outline document icon, decorative.
  2. File nameAs uploaded, wraps anywhere (overflow-wrap: anywhere) so a long camera name never overflows.
  3. MetaType · size · when, in --text-body-sm --color-fg-muted; the error in a failed row.
  4. Actions"Replace" is a small label-button for a hidden file input; "Remove" is a small ghost button. Both name the file for screen readers.
  5. HelpAccepted types and limits, always visible before choosing a file.

Variants

Button trigger

The input comes first, then its label with the button classes. The .file-input:focus-visible + label rule moves the focus ring onto the visible label. Pick the button variant by importance: primary on the photo manager, secondary with an upload icon for the optional certificate, small inside a file row.

File row

Once a single file is attached it is shown as a row, not as the input's native "No file chosen" text. The row is a labelled group so the actions are read in context.

Upload tile (drop target)

A round dashed tile the size of a photo, meant as the last cell of the photo grid on large screens: it echoes the round food photos it will become. It is a label for its own hidden input, so it works by click, tap and keyboard as well as by dropping files on it.

Drop to upload
Default and dragging (data-state="dragging", set while files are over it). Not in the mocks yet.

Sizes

The trigger takes the button sizes: large (52px) in the photos empty state, medium (44px) in the toolbar and the certificate form, small (36px from 48rem, 44px below) inside a file row. The tile is up to 10rem across, the same as a photo tile.

Small · 36px from 48rem, 44px below (row), medium · 44px (toolbar), large · 52px (empty state).

Responsive behaviour

  • Phones: the picker is the operating system's: camera, photo library or files. Never add capture, which would force the camera and hide the library. Uploading, reordering and choosing a cover all work without horizontal scrolling (L2-045.1).
  • The file row wraps: below about 24rem the actions drop under the name, left-aligned (flex-wrap, --space-2 row gap). Names break anywhere rather than overflow.
  • Photo tiles are 2 per row on phones, growing with the photo manager grid; the drop tile, when used, is the last cell and only from 62rem, where dragging files from a desktop is realistic.
  • The toolbar trigger keeps its natural width; it does not become full width, because the photo grid below already fills the screen.

Theming

The trigger is a button and inherits its tokens. The tile reads --color-border-strong (dashed, 2px), --color-fg-muted text, --color-fg-default on hover, and pepper while dragging: --color-accent solid border, --color-accent-subtle fill, --color-fg-accent text, because dragging over it is a "you are here" moment. The file row is a hairline --color-border-default box (a list item edge, not a card shadow); failed swaps to --color-danger-border and --color-danger-fg meta.

In dark the dashed border keeps 3:1 on the near-black canvas and the dragging fill becomes the deep pepper --palette-pepper-950. Nothing on this page has component tokens; re-skin through the semantic ones.

Accessibility

Role and pattern

The native file input is the control; there is no APG pattern for it. The label is its accessible name ("Add photos", "Replace food-handler-certificate.pdf"); aria-describedby points at the accepted types and limits. Drag and drop is an enhancement: every drop target is also a label that opens the picker (WCAG 2.5.7).

Keyboard

KeyAction
TabFocuses the hidden input; the ring shows on its label.
Space / EnterOpens the system file picker.
EscCloses the picker (system behaviour); focus returns to the input.

Focus

Never use display: none or hidden on the input: it would leave the tab order and the label would become an unreachable click target. After files are chosen focus stays on the input; after "Remove" focus moves to the trigger that replaces the row.

Labelling and announcements

  • Repeated actions name their file: "Replace food-handler-certificate.pdf" (the file name is visually hidden), "Cancel upload of IMG_2076.heic", "Move photo 2 up".
  • Each progress bar has role="progressbar", aria-label and aria-valuenow; the percentage drawn over the photo is aria-hidden so it is not read twice.
  • The page status ("Uploading 2 photos…", then "Saved") is a polite role="status"; per-percent changes are not announced.
  • Rejected files are listed in a summary with role="alert" that receives focus; a network failure is a role="alert" toast that does not auto-dismiss.

Motion

The tile's border and text colours change over --duration-fast; progress bars fill over --duration-deliberate; the status dot pulses. Reduced motion stops the pulse and makes the fill instant; the percentages still update.

Touch

Medium and large triggers meet 44px. Below 48rem the small Replace and Remove buttons also grow to 44px (L2-065.1) and wrap under the file name if needed; from 48rem they are 36px with --space-3 between them, clearing the 24px minimum. The tile is far larger than any minimum.

Content

  • Triggers are verb phrases: "Add photos", "Upload a copy", "Replace photo", "Replace". Not "Browse…" or "Choose file".
  • State the limits before the choice, with middle dots between them: "JPEG, PNG, WebP or HEIC · under 15 MB · at least 800 pixels on the shorter side".
  • Rejection messages use L2-041's words and say what happened to the file: "Photos must be under 15 MB and at least 800 pixels on the shorter side", "This file isn’t a JPEG, PNG, WebP or HEIC photo, so nothing was saved".
  • Name files exactly as uploaded; sizes in MB with one decimal ("1.2 MB"); dates like "uploaded Tue 2 Sep".
  • Counts are "6 of 30"; the full message tells people how to make room: "Remove one to add another."
  • Reassure when processing is slow: "You don’t need to upload it again."
