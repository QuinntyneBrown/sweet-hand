Status label

A status label says where a record stands — an enquiry is Open or Replied, a caterer is Published or Suspended, a review is Held. It is always a word plus a shape, never colour alone.

WCAG 2.2 AAStatus: stableL2-069.5.status

Overview

Status labels are the most repeated element in Sweet Hand's working screens: every inbox row, caterer record, review, certificate and account detail ends in one. They carry no fill and no border — a small shape and a medium-weight word in the tone's text colour — so a list of 40 rows stays calm.

  • Use a status label for the state of a record that changes over its life: enquiry, caterer profile, review, report, certificate, email address, device session.
  • Use a badge for a count or a one-word marker that is not a state ("You", "New").
  • Use an alert or inline message when the state needs an explanation or an action ("Your food handler certificate expired on 30 Sep 2026. Upload a current certificate…").
  • Use the save status (.save-status, see forms) for "Saved Tue 2 Sep" after autosave.

Anatomy

  1. Shape8px (--space-2) ::before in the text colour: a filled dot, a square (--radius-xs) or a 2px ring. Decorative; the word carries the meaning.
  2. Word--text-label (14px medium), sentence case, never wraps. It may add a reason after a middot: "Held · contains a phone number".

Sizes

Status labels have one size: the 14px label with an 8px shape. They inherit nothing from surrounding text, so a status in a page intro and one in an inbox row match.

States

Status labels are not interactive: no hover, focus or disabled. They sit on rows that are, so each modifier must hold up on the row's hover fill (--color-bg-surface-sunken) and on the current inbox row (--color-bg-subtle), and in dialogs.

  • Changing state (a caterer declines, an operator suspends) updates the label in place. The change is announced by the action's toast or the dialog's live region, not by the label.
  • Loading: a short text skeleton the width of a typical word; it never guesses a state.

Responsive behaviour

  • Labels never wrap (white-space: nowrap). Containers make room instead: inbox rows put the status on the second line at the right; caterer record rows (.queue-item--stack) move it under the meta below 36rem so "Changes requested" never squeezes a name.
  • In .kv values the status follows the value and drops below it when the row is narrow (the value is a wrapping flex row).
  • Nothing changes at md, lg or xl; the label is the same 14px everywhere.

Theming

The label sets color from a semantic text token and the shape uses currentColor, so one token per modifier drives both: --color-fg-accent (open), --color-success-fg (replied, published), --color-warning-fg (pending, held, changes), --color-danger-fg (declined, suspended), --color-fg-subtle (closed, removed) and --color-fg-muted (draft, hidden, default). In dark each token moves to its light step (pepper-300, callaloo, mango and sorrel tints) to keep 4.5:1 on the stone canvas; shapes don't change. In forced-colours mode the colours drop out and dot, square and ring carry on in CanvasText.

Accessibility

Role and pattern

Plain text in a <span>; no role, no live region. The shape is generated content with no text, so nothing extra is read. This is what WCAG 1.4.1 Use of Color asks for: the word carries the state, the shape repeats it for sighted people who can't separate the hues.

Keyboard

KeyAction
TabNever stops on a status label; it is read as part of its row link or record.

Focus

None of its own; it sits inside focusable rows whose ring encloses it.

Labelling

The word is the accessible text. Inside a row link it is read in DOM order after the name and meta: "Priya Ramdial, Yesterday, Thu 5 Nov · 60 guests · Corporate events, Open". Never use the shape or colour without the word.

The shapes are 8px and drawn in the same colour as the word, so they meet 3:1 wherever the word meets 4.5:1.

Motion

None. Statuses never pulse or blink.

Touch

Not a target.

Content

  • One to three words, sentence case, past participle or adjective: "Replied", "Pending review", "Changes requested". Don't write "Status: Open".
  • Use the same word for the same state on every screen: the customer and the caterer both see "Declined", never "Rejected" on one side.
  • Add the reason or actor after a middot only when the operator needs it: "Held · contains a phone number", "Hidden by Tomas Reyes", "Reverted by Leah Mohammed · Tue 6 Oct".
  • Certificates: "Valid" means not expired; "Expires Mon 9 Nov"; "Expired". Never "Certified" or "Approved" — the certificate is the caterer's own statement.
