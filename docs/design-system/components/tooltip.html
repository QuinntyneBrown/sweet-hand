Tooltip

A tooltip is a short dark label that appears on hover or focus. Sweet Hand's mocks use none: every icon-only button already has an accessible name, and most people browse on phones, where hover does not exist.

Overview

A tooltip repeats or adds to a control's name for mouse and keyboard users: "Close" with its Esc shortcut, or "Move Chicken pelau up" over an arrow. It holds plain text only and never anything you can click.

No current mock uses a tooltip. Icon-only buttons rely on aria-label for their name, and the icons Sweet Hand uses are the conventional few (close, menu, search, arrows, pencil, bin). Where the mocks put icon-only buttons:

  • The site header: search ("Search by area or postal code"), the phone menu ("Menu"), the caterer and operator inbox icon ("Enquiries, 2 unread", "Inbox, 1 unread").
  • Every dialog and sheet: "Close", "Close filters", "Close menu", "Close photo viewer".
  • The menu manager's rows (pages/profile-menu): "Move Chicken pelau up", "Move Chicken pelau down", "Edit Chicken pelau", "Remove Chicken pelau"; the photo manager: "Move photo 3 up".
  • The photo viewer: "Previous photo", "Next photo"; filter chips: "Remove Scarborough".

Add a tooltip only as a desktop enhancement for those row icons, where a mouse user may not know the pencil means edit, and keep the aria-label. If a control needs explaining to everyone, give it a visible label (an icon-and-text button) or a popover.

Anatomy

  1. Label--text-caption in --color-fg-inverse on --color-bg-inverse, padding --space-1 --space-2, --radius-sm, one line.
  2. Shortcut (optional)A <kbd> with a --color-border-inverse outline, --space-2 after the label.
  3. ArrowA 5px CSS triangle in the same inverse colour, centred under the label.
  4. Anchor.has-tooltip wraps the control; the tooltip sits --space-2 above it, centred.

</span>

There is one placement: above, centred. Sweet Hand has no other keyboard shortcuts today, so the shortcut variant applies only to Esc on Close.

Sizes

Tooltips have one size: caption text on one line (white-space: nowrap), sized to the label. Keep labels to three words so they never run off a phone-width screen.

States

Hidden by default. It appears after --duration-hover-delay (300ms) on hover or keyboard focus within the anchor, and disappears instantly when the pointer or focus leaves. data-state="hover" on the anchor or data-state="visible" on the tooltip forces it without the delay.

Both themes

Close Esc
Close Esc
  • Dismissed: Esc hides the tooltip without moving focus (WCAG 1.4.13). This needs a small script; inside a dialog the first Esc hides the tooltip and the second closes the dialog.
  • There is no disabled tooltip. A disabled control cannot take focus, so explain why it is disabled in visible text instead.

Responsive behaviour

  • Touch screens (all widths): no hover, so a tooltip shows only while a focused control keeps focus; never rely on it. This is why the mocks, designed phone first, use none.
  • XS (below 36rem): a tooltip over a control near the screen edge can be cut off because it is centred and does not flip; keep labels to three words, and don't use tooltips on header icons at the edge.
  • MD and up with a mouse: the useful case, such as the menu manager's row icons at 48rem+.

Theming

The tooltip uses the inverse pair: --color-bg-inverse and --color-fg-inverse, the same as the toast. In light it is near-black with white text; in dark it flips to near-white with near-black text, so it always contrasts with the page. The <kbd> outline uses --color-border-inverse; the small shadow is --shadow-2. It stacks highest of all layers (--z-tooltip), above dialogs and toasts.

Accessibility

Role and pattern

APG Tooltip: role="tooltip", shown on hover and focus, referenced with aria-describedby when it adds information. When it only repeats the control's aria-label, mark it aria-hidden="true" so the name is not read twice. The aria-label stays either way: it is the accessible name and what end-to-end tests locate.

Keyboard

KeyAction
TabFocusing the control shows its tooltip after the delay; moving on hides it.
EscHides the tooltip; focus stays on the control.

Focus

The tooltip never takes focus and contains nothing focusable. The control keeps its normal focus ring; the tooltip sits above it, so it never covers the ring.

Labelling

Tooltip text is shorter than the label it supports ("Edit" for "Edit Chicken pelau") because the row gives the context visually; the aria-label names the object for screen readers.

Motion

Opacity fades over --duration-fast after the 300ms delay. The delay is not motion, so reduced motion keeps it and removes only the fade.

Touch

The tooltip adds nothing to the target; the 44px icon button is the target. On touch, a long press shows the system's own menu, not the tooltip, so the label must work without it.

Content

  • One to three words, sentence case, no full stop: "Edit", "Move up", "Close".
  • Describe the action, not the icon: "Remove", not "Bin".
  • Never put information only in a tooltip: allergens, prices, certificate details and error messages are always visible text.

Sources

The tooltip comes from the original kit (docs/mocks/assets/ui.css); no mock uses it. The icon-only buttons it could support are in:

  • pages/profile-menu/default (move, edit and remove each dish)
  • pages/profile-photos/default (move photo up and down)
  • pages/caterers/default (header search and menu)
  • dialogs/photo-viewer/default (previous, next, close)

Drift fixed during extraction: none in the mocks. The kit's tooltip sets pointer-events: none and leaves an 8px gap, so a pointer cannot move onto it without it vanishing (WCAG 1.4.13 "hoverable"); a CSS change is requested, and Esc dismissal needs a script.
